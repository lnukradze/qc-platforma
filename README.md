# NAPR — ხარისხის კონტროლის ერთიანი პლატფორმა (პროტოტიპი, v0.2.0)

ლოკალური (localhost) პროტოტიპი ხელმძღვანელობისა და IT-სთვის. ერთ სისტემაში აერთიანებს:
**განაწილება (სისტემური + სპორადული) → QC შემოწმება → ველის პასუხი → „არ დათანხმებულები“ → სტატისტიკა → Pre-QC**.

შვიდი როლი აქვს:
- კოორდინატორი;
- სამსახურის უფროსი;
- საველე მენეჯერი;
- QC მენეჯერი;
- QC ოპერატორი;
- ამზომველი;
- ადმინისტრატორი.

> არსებულ სისტემებში (Google ცხრილები, REGFIELDALL, განაწილების პროგრამა) პროტოტიპი **არაფერს წერს**.
> მონაცემი მხოლოდ კითხვით მოაქვს. ყველა ცვლილება მხოლოდ ლოკალურ ბაზაში (`data/platform.db`) ინახება.

## გაშვება

| ნაბიჯი | რას აკეთებს |
|---|---|
| `setup.bat` (ერთხელ) | ქმნის Python-ის გარემოს (`.venv`) და აყენებს ბიბლიოთეკებს. შემდეგ Google ცხრილებიდან მონაცემი მოაქვს (**მხოლოდ კითხვით**) და აწყობს ლოკალურ ბაზას |
| `run.bat` | უშვებს სერვერს და ხსნის ბრაუზერს: <http://127.0.0.1:8200> |
| `run_lan.bat` | იგივეა, ოღონდ იმავე ქსელში მყოფი ტელეფონიდან/პლანშეტიდანაც იხსნება. ყოველ გაშვებაზე იქმნება ახალი **დემო კოდი (PIN)**, რომლის გარეშეც შესვლის გვერდზე მომხმარებლების სიაც არ ჩანს |

საჭიროა Windows და [uv](https://docs.astral.sh/uv/) (`winget install astral-sh.uv`) ან Python 3.12+.
კორპორატიული სერტიფიკატი Windows-ის საცავიდან იკითხება (`truststore`).

**შესვლა.** დემო რეჟიმში ადამიანს სიიდან ირჩევთ. Google-ით შესვლა ჩაშენებულია და ჩაირთვება, როცა IT OAuth კლიენტს შექმნის (იხ. ქვემოთ).
ვისაც რამდენიმე როლი აქვს, როლს ზედა ზოლში ცვლის. წარდგენის სცენარი — [docs/DEMO.md](docs/DEMO.md).

**API (IT-სთვის):** <http://127.0.0.1:8200/docs> — OpenAPI აღწერა. ყველა endpoint ხილვადობის იმავე წესებს ექვემდებარება, რასაც გვერდები.

## მონაცემის განახლება

```bat
.venv\Scripts\python.exe scripts\fetch_sheets.py fetch   :: Google ცხრილები → data\raw (მხოლოდ GET)
.venv\Scripts\python.exe scripts\build_db.py             :: data\raw → data\platform.db (≈ 2 წთ)
```

⚠️ `build_db.py` ბაზას ნულიდან აწყობს. პროტოტიპში შეტანილი ცვლილებები იკარგება: განაწილება, პასუხები, ფოტოები, მინიჭებები, მეილები.
სერვერი ამ დროს გაჩერებული უნდა იყოს.

## კონფიგურაცია (საწარმოოსთვის)

ყველა პარამეტრი გარემოს ცვლადია. კოდის შეცვლა საჭირო არ არის.

| ცვლადი | დანიშნულება |
|---|---|
| `QCP_DATABASE_URL` | ბაზა, მაგ. `postgresql+psycopg://…` (ნაგულისხმევი — SQLite `data\`-ში) |
| `QCP_DATA_DIR` | მონაცემის/ფაილების საქაღალდე |
| `QCP_SESSION_SECRET` | სესიის გასაღები. თუ არ არის მითითებული, ერთხელ იქმნება `data\.session_secret`-ში; საწარმოოში უმჯობესია სერვერის საიდუმლოების საცავიდან |
| `QCP_DEMO_LOGIN` = `0` | სიიდან შესვლის გამორთვა (მხოლოდ Google) |
| `QCP_GOOGLE_CLIENT_ID`, `QCP_GOOGLE_CLIENT_SECRET`, `QCP_GOOGLE_ALLOWED_DOMAIN` | Google-ით შესვლა; redirect: `https://<დომენი>/auth/google/callback` |
| `QCP_BASE_URL` | საჯარო მისამართი (მეილის ბმულებისთვის) |
| `QCP_SMTP_HOST`, `_PORT`, `_USER`, `_PASSWORD`, `_FROM`, `_STARTTLS` | მეილის გაგზავნა |

IT-სთვის მოთხოვნები და რეკომენდაცია — [docs/IT_REQUEST.md](docs/IT_REQUEST.md).

## მონაცემის დაცვა

- `data\` შეიცავს რეალურ სახელებს, QC კომენტარებს, ფოტოებს და პირად ნომრებს. **არ გაავრცელოთ**:
  არც ფოსტით, არც საზიარო საქაღალდეში. `.gitignore` მას ვერსიირებიდან გამორიცხავს.
- სპორადულის ფაილში განმცხადებლების პირადი ნომრები და ტელეფონებია. პლატფორმა მხოლოდ საჭირო სვეტებს კითხულობს. ატვირთული ასლი დამუშავებისთანავე იშლება.
- Apps Script-ის token-ები არსად იბეჭდება და `data\`-ში არ ინახება. კავშირის კონფიგურაცია
  არსებული პროექტების ფაილებიდან (`sheet_config.json`, `config.json`) იკითხება.
- `run_lan.bat` მხოლოდ მოკლე, დახურული ჩვენებისთვისაა. დასრულებისთანავე დახურეთ ფანჯარა.
