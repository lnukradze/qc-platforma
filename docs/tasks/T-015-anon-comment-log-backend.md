## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილებები (`docs/OPEN_QUESTIONS.md`, 2026-10-26):
- **კონტროლი ველისთვის ანონიმურია** — ამზომველს და საველე მენეჯერს QC ოპერატორის / QC მენეჯერის სახელი არსად უჩანს, მხოლოდ `D.QC_ANON_LABEL` („ხარისხის კონტროლი“).
  კონტროლის ცვლილებების ლოგს ველი ვერ ხედავს; კონტროლი ველის ლოგს ხედავს (სახელებით).
- **კომენტარის რედაქტირება** — ყოველ შენახვას ლოგი აქვს; ჩანს „ბოლო ცვლილება — ვინ · დრო“. QC მენეჯერს გადაწყვეტილების შემდეგ ახსნის რედაქტირება შეუძლია.

ახლა სახელი ველს **ექვს ადგილას** უჩანს: ბარათი („QC ოპერატორი“), ისტორია (`e.actor.full_name`), მთავარი („ბოლო მოქმედებები“),
„ახლა ხსნის“ (`/api/presence*` → `name`), API (`/api/items*` → `operator`), მეილი საველე მენეჯერს („გამომგზავნი: …“).
შაბლონების გადაწყობა — T-016 (ბარათი) და T-014 (მთავარი), ამ კონტრაქტით.

**შედის:**
1. **ერთი წესი** — ფუნქცია (მაგ. `app/services/anon.py`): `actor_name(viewer_role, user, actor_role) -> str`.
   თუ მნახველი ველის როლშია (`D.FIELD_ROLES`) და მოქმედი QC-ის როლში იყო (`D.QC_ROLES`, ან `actor_role` არ არის და მომხმარებელს QC როლი აქვს) → `D.QC_ANON_LABEL`; სხვა შემთხვევაში — სრული სახელი.
   შაბლონებს გადაეცემა `render()`-ით (`routes/common.py`): `actor_name(user, actor_role)` — მნახველი `ctx`-იდან.
2. **ბარათი** (`routes/items.py`): `show_operator = ctx.role not in D.FIELD_ROLES`; ველის როლზე `operators` / გადანაწილების მონაცემი არ გადაეცემა.
3. **API:** `/api/items`, `/api/items/{id}` — ველის როლზე `operator` არ ბრუნდება; `/api/presence`, `/api/presence/{id}` — ველის მნახველს QC-ის `name` → `D.QC_ANON_LABEL`.
4. **მეილი** (`services/notify.py`): მიმღები ველის როლშია → გამომგზავნი `D.QC_ANON_LABEL`. შაბლონს გადაეცემა `sender_name`;
   `app/templates/email/notice.html` და `notice.txt`-ში `sender.full_name` → `sender_name` (**ამ ორი ფაილის ეს ხაზები — ნებადართული გამონაკლისი**).
5. **მთავარი** (`routes/pages.py`) — „ბოლო მოქმედებები“: ველის მნახველზე სახელი `actor_name`-ით (შაბლონი — T-014; T-013-თან ერთად ლიმიტი 10).
6. **ლოგი ველისთვის დამალულია:** QC-ის რედაქტირების მოვლენები (`edited`, ახალი `qcm_comment_edited`) — `scope.QC_INTERNAL_EVENTS`-ში.
   ველი ხედავს მიმდინარე ტექსტს და „ბოლო ცვლილება — ხარისხის კონტროლი · დრო“-ს.
7. **კომენტარის ლოგი:** `edited`-ში `data`-ს ემატება `{"field": "qc_comment", "before": …, "after": …}`; ახალი ქმედება **`qcm_comment_edit`** (QC მენეჯერი, ადმინი;
   როცა `item.qcm_decision` არის): ცვლის `item.qcm_explanation`-ს, მოვლენა `qcm_comment_edited` `before/after`-ით; ცარიელი ახსნა `qcm_stand`-ზე — უარი (როგორც ახლა).
   `available_actions`-ში — სწორ როლსა და მდგომარეობაზე.
8. **„ბოლო ცვლილება“** — ბარათს გადაეცემა `last_change`: `{"qc_comment": {"at", "who"}, "field_comment": {…}, "qcm_explanation": {…}}`
   (უკანასკნელი შესაბამისი მოვლენიდან; `who` — უკვე `actor_name`-ით; ცარიელი → `None`).

**არ შედის:** შაბლონები (გარდა მეილის ორი ხაზისა) — T-014, T-016; QC-ის მხარეს სახელები არ იმალება; Pre-QC.

**ფაილები (ზონა):** `app/services/` (ახალი + `notify.py`), `app/routes/common.py`, `items.py`, `api.py`, `pages.py`, `app/workflow.py`, `app/scope.py`,
`app/templates/email/notice.*` (მხოლოდ გამომგზავნის ხაზი).

**კონტრაქტი (backend ↔ ui):**

| სახელი | სად | შინაარსი |
|---|---|---|
| `actor_name(user, actor_role)` | ყველა შაბლონი (`render`) | სახელი ან „ხარისხის კონტროლი“ — მნახველის როლით |
| `show_operator` | `items/detail.html` | „QC ოპერატორის“ სტრიქონი ჩანს? |
| `last_change` | `items/detail.html` | `{"qc_comment"\|"field_comment"\|"qcm_explanation": {"at": datetime, "who": str} \| None}` |
| ქმედება `qcm_comment_edit` | POST `/items/{id}/action` | ველები: `comment`, `version` |
| მოვლენის `data.before` / `data.after` | ისტორია (QC-სთვის) | რა შეიცვალა |

**დასრულების პირობა** (ტესტირებადი):
1. pytest (ახალი `tests/test_anon.py` — ნებადართული გამონაკლისი): ამზომველის და საველე მენეჯერის როლით `/items/{id}`, `/`, `/api/items`, `/api/items/{id}`,
   `/api/presence*` და მათთვის შექმნილი მეილის ტექსტი **არ შეიცავს** QC ოპერატორის / QC მენეჯერის სახელს და შეიცავს „ხარისხის კონტროლი“-ს, სადაც მოქმედი QC-ია.
2. QC მენეჯრით იგივე გვერდებზე ველის ადამიანის სახელი ჩანს.
3. `edited` და `qcm_comment_edited` ველის ისტორიაში არ ჩანს; QC-ის ისტორიაში ჩანს `before/after`-ით.
4. `qcm_comment_edit`: QC მენეჯერი — მუშაობს; ოპერატორი / საველე — უარი; გადაწყვეტილების გარეშე — უარი.
5. `last_change` სწორია სამივე კომენტარზე; ველისთვის `who` = „ხარისხის კონტროლი“.
6. `pytest -q` გადის; `smoke_pages.py` დემო ბაზაზე — 0 შეცდომა.
