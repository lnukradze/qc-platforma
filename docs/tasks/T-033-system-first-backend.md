## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილება (`docs/OPEN_QUESTIONS.md`, „სისტემური სერვისის ოქმები განაწილებაში“, 2026-10-28):
სისტემურ განაწილებაში **არ შედის** კოდი, რომლის **პირველი** ოქმი „სისტემურმა სერვისმა“ შექმნა (`OQMI_CREATOR`), მაშინაც კი,
როცა მოგვიანებით ამზომველმა მასზე ოქმი დააკავშირა (მაშინ `OQMI_CREATOR`-ში ამზომველი წერია). ასეთი კოდი სპორადულია:
სპორადულის ინფორმაცია ცალკე მოდის და ცალკე სიით ნაწილდება (IT-ის ყოველდღიური სია, `services/sporadic.py`) — **სპორადული უცვლელია**.

ახლა (`services/distribution/source.py`, `query_candidates`) „სისტემური სერვისის“ ოქმები **სრულად იგნორირდება**: პირველ ოქმად
უადრესი არა-სისტემური ითვლება, ამიტომ ასეთი კოდი ამზომველის ოქმის თარიღით შედის განაწილებაში.

მაგალითი: კოდი X — 01.09 „სისტემური სერვისის“ ოქმი, 15.10 ამზომველის ოქმი. ახლა X შედის 15.10-ის დიაპაზონში; ახალი წესით — არცერთში.

**შედის:**
1. **კანდიდატის წესი** (`query_candidates`): კოდი შედის, თუ მისი პირველი ოქმი — **ყველა** ჩანაწერს შორის, დალაგება როგორც ახლა
   (`mox_create_date`, შემდეგ `fld_paper_id`) — **არ არის** „სისტემური სერვისის“ და მისი თარიღი დიაპაზონშია. იმავე დღეს უფრო ადრე
   შექმნილი სისტემური ოქმიც გამორიცხავს კოდს. თარიღის გარეშე ჩანაწერები — როგორც ახლა. დანარჩენი ველები უცვლელია
   (`protocol_count`-ის წესი — T-017).
2. **ნაშთი** (`DistributionBacklog`, `status="open"`, წინა განაწილებებიდან): გადახედვისას იმავე წესით მოწმდება (წყაროდან, ერთი მოთხოვნით);
   წესს თუ არ აკმაყოფილებს — არ ნაწილდება, დადასტურებისას `status="excluded"`.
3. **გადახედვის რიცხვი:** `counts.system_first` — რამდენი კოდი გამოირიცხა ამ წესით (დიაპაზონი + ნაშთი). გვერდზე ჩვენება (ერთი ხაზი
   გადახედვის ძაბრში) — ui, „სხვა როლებისგან სჭირდება“.
4. **დემო წყარო** (`scripts/build_demo_db.py`, `distributor.sqlite`): 2–3 X-ის მსგავსი კოდი, რომ ბრაუზერშიც შემოწმდეს.
5. `source.py`-ის docstring — ახალი წესით.

**არ შედის:** სპორადული (`services/sporadic.py`) — უცვლელი; **უკვე განაწილებული ოქმები** (`QcItem`) არ იცვლება — წესი უკანა თარიღით
არ ვრცელდება; ოქმების რაოდენობა — T-017; შაბლონები; `models.py` (lead-მა `status`-ის კომენტარი უკვე განაახლა).

**ფაილები (ზონა):** `app/services/distribution/source.py`, `app/services/distribution/service.py`, `scripts/build_demo_db.py`,
`tests/test_distribution_source.py` (ახალი — ნებადართული გამონაკლისი).

**კონტრაქტი (backend ↔ ui):** გადახედვის `counts.system_first` (int) — ჩვენებისთვის.

**დასრულების პირობა** (ტესტირებადი):
1. pytest, გამოგონილი წყარო (დროებითი SQLite `parcels`, `query_candidates(..., path=)`):
   X (01.09 სისტემური, 15.10 ამზომველი) → არცერთ დიაპაზონში; Y (01.09 ამზომველი, 15.10 სისტემური) → 01.09-ის დიაპაზონში კი, 15.10-ისაში — არა;
   Z (მხოლოდ ამზომველი) → როგორც ახლა; W (მხოლოდ სისტემური) → არა; იმავე დღეს 10:00 სისტემური, 12:00 ამზომველი → არა.
