## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილება (`docs/OPEN_QUESTIONS.md`, „ოქმების რაოდენობა საკადასტრო კოდზე“, 2026-10-26): განაწილებისას ინიშნება,
რამდენი ოქმია შედგენილი კოდზე; ბარათზე — „202.67.04.42.003.029 · ოქმების რაოდენობა: 2“ (ბარათი — T-016).
lead-მა უკვე დაამატა ცხრილი `CadProtocolCount` (`cadcode`, `count`, `updated_at`).

**შედის:**
1. **სისტემური განაწილება** — დადასტურებისას (`confirm`) ყოველ განაწილებულ კოდზე `CadProtocolCount`-ის ჩაწერა / განახლება გადახედვის `protocol_count`-იდან
   (`services/distribution/source.py` უკვე ითვლის).
2. **სპორადული** — დადასტურებისას იგივე, წყაროდან იმავე დათვლის წესით (ახალი ფუნქცია `source.py`-ში: კოდების სია → რაოდენობა, ერთი მოთხოვნით, `mode=ro`).
   წყარო არ არის → რაოდენობა არ იწერება, განაწილება არ ჩერდება.
3. **ძველი ოქმები** — `scripts/backfill_protocol_counts.py`: ყველა კოდი `qc_items`-იდან → წყარო (მხოლოდ კითხვა) → `CadProtocolCount`.
   იბეჭდება: რამდენი კოდი, რამდენი განახლდა, რამდენი ვერ მოიძებნა. **რეალურ ბაზაზე მას ადამიანი უშვებს** (აგენტი — მხოლოდ დემოზე).
4. ბარათის კონტექსტი (`routes/items.py`): `protocol_count` (int | None); `/api/items/{id}` — `"protocol_count"`.
5. `scripts/build_demo_db.py` — დემო კოდებზე რაოდენობა (ზოგზე 2–3).

**არ შედის:** შაბლონი (T-016); `models.py` (უკვე არის); განაწილების ალგორითმის ცვლილება.

**ფაილები (ზონა):** `app/services/distribution/*`, `app/services/sporadic.py`, `app/routes/items.py`, `app/routes/api.py`, `scripts/backfill_protocol_counts.py` (ახალი), `scripts/build_demo_db.py`.

**კონტრაქტი (backend ↔ ui):** `items/detail.html` — `protocol_count`: int | None.

**დასრულების პირობა** (ტესტირებადი):
1. pytest (ახალი `tests/test_protocol_count.py` — ნებადართული გამონაკლისი; გამოგონილი წყარო): სისტემური და სპორადული დადასტურება წერს რაოდენობას; განმეორებით — განახლებს.
2. წყაროს გარეშე სპორადული განაწილება მუშაობს, რაოდენობა — `None`.
3. backfill დემო ბაზაზე: ბეჭდავს სამ რიცხვს; მეორე გაშვება — იგივე შედეგი.
4. `/api/items/{id}` აბრუნებს `protocol_count`-ს; `pytest -q` გადის; `smoke_pages.py` — 0 შეცდომა.
