## 1. ბრიფი — lead

**მიზანი:** T-029-მა ველს QC-ის სახელი და ავტორის როლი დაუმალა, მაგრამ QA-მ (`6ef3128`) აჩვენა, რომ QC-ის როლი ისევ იკითხება
**წარწერებში**: მოვლენის სათაური („QC მენეჯერი: ხარვეზი რჩება“), სტატუსი („არ დათანხმებული — QC მენეჯერთან“), ბარათის „QC მენეჯერის ახსნა“,
წერილი, API (`role`, `state_label`). QC მენეჯერი 1–2 ადამიანია — როლი ვინაობას ამხელს.

**წესი (ლუკა, 2026-10-27, `OPEN_QUESTIONS.md`):** ველის როლით (ამზომველი, საველე მენეჯერი — აქტიური როლი) **ნებისმიერ გვერდზე, წერილში და API-ში**
არ ჩანს: „QC მენეჯერ…“, „QC ოპერატორ…“, „კონტროლის მენეჯერ…“, „კონტროლის ოპერატორ…“, „ოპერატორის შეცდომა“; API-ში — `qc_manager`, `qc_operator`, `admin`
როგორც მოქმედების როლი. მათ ნაცვლად — „ხარისხის კონტროლი“ (`D.QC_ANON_LABEL`) ან ნეიტრალური ფორმა. **გამონაკლისი — მხოლოდ „შესახებ“ გვერდი** (`/about`).
QC როლებისთვის, ადმინისა და კოორდინატორისთვის ყველაფერი რჩება, როგორც ახლაა.
**ტექნიკური კოდები — უცვლელი** (ლუკა, 2026-10-28): `state` `awaiting_qcm`, `action` `qcm_*`, `close_reason` `qc_error` — ველისთვისაც იგივე,
API-ში, ფილტრსა და მისამართში. წესი ფარავს ტექსტს და ავტორს, არა კოდს. QA-ის ტესტი კოდებს აკრძალულ სიტყვად არ ითვლის.

**კონტრაქტი (lead, უკვე main-შია — `app/domain.py`):**
- `D.FIELD_EVENT_LABELS`, `D.FIELD_STATE_LABELS`, `D.FIELD_QCM_DECISION_LABELS` — სრული ლექსიკონები, ველისთვის შეცვლილი წარწერებით
  (მაგ. `qcm_stand` → „ხარისხის კონტროლი: ხარვეზი რჩება“, `AWAITING_QCM` → „არ დათანხმებული — ხარისხის კონტროლთან“, `QCM_FIELD_RIGHT` → „ველი მართალია“).
- `D.labels(role)` → `{"EVENT_LABELS", "STATE_LABELS", "QCM_DECISION_LABELS"}` — ველის როლს ნეიტრალური, სხვას სრული. **ერთადერთი წყარო** —
  წარწერას ცალკე არავინ წერს; ახალი წარწერა სჭირდება → lead-ს სთხოვე.

### ნაწილი ა — ui

**შედის:**
1. შაბლონები `EVENT_LABELS` / `STATE_LABELS` / `QCM_DECISION_LABELS`-ს კონტექსტიდან იღებს (ნაწილი ბ-ს `render()` როლით აწვდის).
   ⚠️ `{% from "_macros.html" import … %}` კონტექსტს არ ხედავს — `state_chip` და სხვა მაკრო გლობალურ (სრულ) წარწერას დაბეჭდავს.
   გამოსავალი შენი არჩევანია (`with context`, ან წარწერა პარამეტრად), ოღონდ ერთნაირად ყველგან.
2. ველისთვის ხილული ჩაწერილი ტექსტები — ველის როლით ნეიტრალურად: `items/detail.html` — „QC მენეჯერის ახსნა“ (`:198`), stepper-ის მინიშნება
   „მენეჯერი / QC მენეჯერი“ (`:33`), „კონტროლის მენეჯერთან / მენეჯერს“ (`:210`, `:217`); `home.html` — „QC მენეჯერის გადაწყვეტილება“, „QC მენეჯერთან“
   (`:190`, `:202`, თუ ველს უჩანს); `stats/index.html` — „ხედავს: … QC მენეჯერი …“ (`:119`) და ოპერატორის ველები, თუ ველს უჩანს;
   `preqc/index.html:11` — „კონტროლის ოპერატორს…“. ეს სია სრული არ არის — გადაამოწმე **ყველა** გვერდი, რომელიც ველს უჩანს.
3. წერილი (`email/notice.html`, `email/notice.txt`): `D.EVENT_LABELS` → `EVENT_LABELS` (ნაწილი ბ აწვდის ველისას).
4. T-029-ის წვრილმანი: `items/detail.html:147` მძიმის და `:405` „·“-ის შემდეგ ჰარი.

**ფაილები (ზონა):** `app/templates/`, `app/templating.py`.

### ნაწილი ბ — backend

**შედის:**
1. `routes/common.py` → `render()`: `context.update(D.labels(viewer_role))` — ყველა გვერდი მნახველის როლის წარწერებს იღებს.
2. `routes/api.py`: `state_label` — `D.labels(ctx.role)["STATE_LABELS"]`; ისტორიაში `role` — **არ** ბრუნდება, თუ `anon.hidden(...)`
   (როგორც presence-ში, `_others`). სხვა ველები, რომლებშიც QC-ის როლი ან სახელი შეიძლება მოხვდეს — გადაამოწმე.
3. `services/notify.py` → `queue()`: შაბლონის კონტექსტს ემატება `**D.labels(D.FIELD_MANAGER)` — ადრესატი ყოველთვის საველე მენეჯერია (T-030),
   ამიტომ წერილი ყოველთვის ნეიტრალურია (ორმაგი როლის ადრესატისთვისაც). `SUBJECTS` უკვე ნეიტრალურია — გადაამოწმე.

**ფაილები (ზონა):** `app/routes/common.py`, `app/routes/api.py`, `app/services/notify.py`.
ნაწილი ა და ბ ერთმანეთს არ ელოდება: სანამ ბ არ არის, შაბლონი გლობალურ (სრულ) წარწერას იღებს — როგორც ახლა.

### ნაწილი გ — qa

**შედის:** ერთი რეგრესიის ტესტი (`tests/`), რომელიც ამ წესს მომავალშიც იცავს — T-016, T-014, T-020 ბარათსა და მთავარს გადააკეთებს:
1. ორივე ველის როლით (მხოლოდ ველის როლის მქონე მომხმარებელი) — ყველა გვერდი, რომელიც ველს უჩანს (`/about`-ის გარდა), იმ ოქმებით, სადაც
   QC მენეჯერის გადაწყვეტილება, სტატუსის შეცვლა და ოპერატორის შეცდომა არის: HTML-ში აკრძალული სიტყვა **არ** არის.
2. API (`/api/items`, `/api/items/{id}`) ველის როლით: `state_label`-ში აკრძალული სიტყვა არ არის; ისტორიის არცერთ ჩანაწერს არ აქვს `role` QC-ის როლით.
3. წერილი (`EmailMessage.html` / `.text`) QC მენეჯერის გადაწყვეტილებაზე და კომენტარზე: აკრძალული სიტყვა არ არის.
4. საკონტროლო: იგივე ოქმი QC მენეჯრით — „QC მენეჯერი“ წარწერებში **ჩანს** (ტესტი ცარიელ გვერდზე არ „მწვანდება“).

აკრძალული სიტყვების სია — ერთ ადგილას, ტესტში; `D.ROLE_SHORT` / `D.ROLE_LABELS`-იდან, სადაც შესაძლებელია.

**არ შედის:** ბარათისა და მთავარის დიზაინი (T-016, T-014); QC მხარის წარწერები; ბაზა; „შესახებ“ გვერდი.

**დასრულების პირობა** (ტესტირებადი, სამივე ბრენჩი ერთად):
1. ნაწილი გ-ს ტესტი გადის; `pytest -q` — 0 failed, 0 xfailed.
2. დემო ბაზა, ბრაუზერი: საველე მენეჯრითა და ამზომველით — მთავარი, სიები, ბარათი (დავიანი ოქმი), სტატისტიკა, Pre-QC: აკრძალული სიტყვა არსად;
   იგივე ოქმი QC მენეჯრით — წარწერები უცვლელია.
3. `smoke_pages.py` დემო ბაზაზე — 0 შეცდომა.

**ჩაბარებისას შევამოწმებ:** წარწერა მხოლოდ `D.labels()`-იდან მოდის (შაბლონში ან კოდში ახალი ხელით ჩაწერილი „QC მენეჯერი“ ველისთვის არ არის);
მაკროები ველის წარწერას იღებს; წერილის ორივე ვერსია; API-ის `role`.
