## 1. ბრიფი — lead

**მიზანი:** ლუკას მოთხოვნა (2026-10-26): QC მენეჯერის მთავარი გვერდი — მხოლოდ ის, რაც ყოველდღიურ მართვას სჭირდება.
ადმინს იგივე გვერდი აქვს (ადმინის „მონაცემთა წყაროები“ და „გადმოტანის შედეგი“ რჩება).

**ორ ნაწილად:**
- **ა — ახლავე:** პუნქტები 1, 2, 5.
- **ბ — T-013-ის ჩაბარების შემდეგ** (კონტრაქტი `rep_day`, `rep_week`, `rep_adjustments`, `rep_operators`): პუნქტები 3, 4.

**შედის:**
1. **„ოპერატორების დატვირთვა ახლა“** — სორტირება **ყველა სვეტით** (სათაურზე დაჭერა: ზრდადი / კლებადი; `aria-sort`; კლავიატურით მისაწვდომი; JS ბრაუზერში, სერვერის გარეშე).
2. QC მენეჯერსა და ადმინზე **არ ჩანს:** „პრე ხარვეზები“, „ხარისხის კონტროლის ხარვეზები“, „ხარვეზების სტატისტიკა“ (სხვა როლებზე — უცვლელი).
3. **ოპერატორების რეპორტი — ერთ ბლოკში:** თავიდან ჩანს **დღე** (`rep_day`: ოპერატორი — გავლილი; სტატუსი — წარწერით; ჯამი).
   „კვირის ნახვა“ → იშლება **მიმდინარე კვირა** (`rep_week`: ორშ–პარ × ოპერატორი, ჯამები; შაბ/კვ — არა).
   ბმული „სრული რეპორტი →“ — `/reports/operators` (T-018). ხელით შესწორებული უჯრა — შესამჩნევი ნიშნით (DESIGN.md-ის ფერებით, წარწერით).
4. **შესწორების ფორმა** (QC მენეჯერი, ადმინი) — **საერთო partial T-018-თან**: ოპერატორი, დღე, სახე (შესწორება / შვებულება / ბიულეტინი /
   სამსახურეობრივი დავალება / დეიოფი — `D.REPORT_ADJ_KINDS`), +/− რაოდენობა, „მეორე ოპერატორს დაუწერე“ (გადატანა), სტატუსზე — პერიოდი, შენიშვნა (სავალდებულო).
   ქვემოთ — კვირის შესწორებების ლოგი (ვინ, როდის, რა) და „გაუქმება“.
5. **„ბოლო მოქმედებები“** — 10 ჩანაწერი (backend-იდან; შაბლონში ლიმიტი არ ჭრის). **ყველა როლზე** სახელი — `actor_name(e.actor, e.actor_role)`-ით
   (T-015; U-03 / U-33 — ველს QC-ის სახელი არ უჩანს), ველის როლზე მდგომარეობის ჩიპი — ველის წარწერით.
6. **ერთი ძირითადი ღილაკი** QC მენეჯერისა და ადმინის მთავარზე (A01-ის ეს ნაწილი; დანარჩენი როლები — T-027).

**არ შედის:** Python (T-013); სხვა როლების მთავარი გვერდი (გარდა პუნქტი 5-ისა); ახალი დიზაინის ელემენტები DESIGN.md-ის გარეთ.

**ფაილები (ზონა):** `app/templates/home.html` (და საჭიროების შემთხვევაში ახალი partial), `app/static/css/app.css`, `app/static/js/app.js`.

**კონტრაქტი (backend ↔ ui):** `rep_day`, `rep_week`, `rep_adjustments`, `rep_operators`, ფორმის ველები და route-ები — T-013-ის ბრიფში (ცხრილი).

**დასრულების პირობა** (ტესტირებადი):
1. დატვირთვის ცხრილი ყოველი სვეტით სორტირდება ორივე მიმართულებით; Tab + Enter მუშაობს.
2. QC მენეჯრითა და ადმინით სამი ბლოკი არ ჩანს; ოპერატორით / საველე მენეჯრით — ისევ ჩანს.
3. დემო ბაზაზე: დღის ცხრილი → „კვირის ნახვა“ → 5 სვეტი (ორშ–პარ), ჯამები; „სრული რეპორტი →“ ხსნის `/reports/operators`-ს.
4. შესწორება „+2“ ერთ ოპერატორზე → ჯამი იცვლება და ლოგში ჩნდება; „გაუქმება“ → ბრუნდება; ბიულეტინი → წარწერა უჯრაში.
5. 1366px და 390px, ღია და მუქი — ჰორიზონტალური გადაცურება გვერდზე არ ჩნდება (კვირის ცხრილი — საკუთარი გადაცურებით); კონსოლი სუფთა.
6. `pytest -q` გადის; Hallmark — ახალი FAIL არ გაჩნდა.

**ჩაბარებისას შევამოწმებ:** ვიზუალი — 1366 / 390px, ღია / მუქი; რეპორტის რიცხვები = T-013-ის ტესტის რიცხვები.
