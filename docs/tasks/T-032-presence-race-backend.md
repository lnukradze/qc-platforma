## 1. ბრიფი — lead

**მიზანი:** QA-მ ერთობლივ აუდიტში (2026-10-28) `/api/presence/{id}` ping / leave-ის პარალელურ სცენარში 100 ცდიდან 16-ზე მიიღო HTTP 500
(`StaleDataError`): ping ORM-ით კითხულობს ჩანაწერს და მერე ცვლის, ამასობაში leave ან წმენდა მას შლის. მონაცემი არ ზიანდება (presence დროებითი
სიგნალია), მაგრამ 500 ლოგს ავსებს და ბრაუზერის „ახლა ხსნის“ წყდება. **ლუკა (2026-10-28):** production-ის ბლოკერია, merge-ის — არა.

**შედის:**
1. `presence_ping`: ერთი ატომური upsert (`INSERT … ON CONFLICT DO UPDATE`, T-019-ის `_insert` — SQLite / PostgreSQL); ძველი დრო ახალს არ გადაწერს.
2. ძველი (> 10 წთ) ჩანაწერების წმენდა — ping-ის commit-ის შემდეგ, ცალკე; ბაზა დაკავებულია → გამოტოვება და `warning` (სახელის გარეშე), არა 500.
3. `presence_leave` — უკვე `DELETE … WHERE`-ია (არ არსებობს → 200) — უცვლელი.
4. ანონიმურობა (T-015 / T-031) უცვლელია: `_others` ველს QC-ის სახელს და როლს არ უჩვენებს.

**არ შედის:** presence-ის UI; სხვა API.
