## 2. პრომპტი შემსრულებლისთვის — qa (Codex)

> ბრიფს არ ცვლის — მხოლოდ „როგორ“-ს ამატებს. დასრულების პირობა ნაწილი 1-იდან სიტყვასიტყვით.

### დაწყების წინაპირობა და კონტექსტი

შენ ხარ **ui**. მიზანია „იზოხაზის“ არსებული ინტერფეისის მობილური გამოყენებისა და ხელმისაწვდომობის ხარვეზების გამოსწორება, ახალი დიზაინის სისტემის გარეშე. სამუშაო ბრენჩია `ui/T-025-mobile-a11y`.

**განხორციელება დაიწყე მხოლოდ მას შემდეგ, რაც ლუკა T-012-ის ნაწილი ა-ს main-ში მიიღებს, თუ ლუკა სხვა რიგს პირდაპირ არ დაამტკიცებს.** ნაწილი 1-ის ძველი მითითება „შეიძლება მაშინვე“ არ ცვლის ამ დავალებისთვის მოგვიანებით დადგენილ დაწყების რიგს; ბრიფის ტექსტი უცვლელად რჩება. დაწყებამდე განახლებული main-იდან წაიკითხე T-012-ის ჩაბარების ჩანაწერი/ლუკას დასტური და დარწმუნდი, რომ მიიღო საბოლოო ცვლილებები, მათ შორის სტატუსის ფილტრის დამალვა და სამი განახლებული UI ტესტი (`89c3910`/`50458a1` — სამიზნე ბრენჩის მტკიცებულებები, არა main-ში მიღების ავტომატური დასტური). main-ში მხოლოდ QA ოქმის არსებობა ან განხორციელების ბრენჩზე commit **არ ნიშნავს** T-012ა-ს ჩაბარებას. ჩაბარების გარეშე — **BLOCKED განხორციელებისთვის**, დოკუმენტის წინასწარ მომზადება დასაშვებია.

წაიკითხე `AGENTS.md`, `docs/team/roles/ui.md`, `docs/team/SALOME.md`, `DESIGN.md`, `docs/team/checklists/visual.md`, T-012-ის გადაწყვეტილებები და ამ დოკუმენტის ნაწილები 1–2. არსებული ბრენჩი/დაუკომიტებელი სამუშაო არ გადაწერო; reset/stash/force არ გამოიყენო. main-ში განხორციელების კოდი არ ჩაწერო — ჩაბარება და merge lead-ისაა.

### განხორციელების ნაბიჯები

1. **საწყისი გაზომვა მიღებულ T-012ა-ზე.** შეინახე არჩეული base commit, საწყისი screenshot-ები, viewport/device scale, root/body ზომები, პატარა კონტროლების ზომები, კონსოლის/network შეცდომები და კონტრასტის წყვილები. იმუშავე გამოგონილ დემოზე. შემდეგი შედარება სწორედ მიღებულ base-ს მიაბი; ძველი აუდიტის ვერდიქტი ახლანდელი browser მტკიცებულების ნაცვლად არ გამოიყენო.

### დარჩენილი ხარვეზები და რისკები

1. **[მნიშვნელოვანი — UI, T-025] Drawer-ის შეხების ზომა:** `.drawer-foot button[data-dmove="-1"]` და `[data-dmove="1"]` ორივე ველის როლით, 390/360px-ზე, light/dark-ში არის **40×44 CSS px**. მტკიცებულება: `getBoundingClientRect()`, ყველა 8 drawer სცენარში, ჯამში 16 ღილაკის გაზომვა. გენერირდება `app/static/js/app.js`-ის `openPeek()`-ში (`btn btn-ghost btn-sm`); `app.css`-ის მობილური `.btn/.btn-sm` წესი მხოლოდ სიმაღლეს ზრდის. **სხვა როლებისგან სჭირდება — UI:** რეალური button box-ის სიგანე მინიმუმ 44px და ხელახალი გაზომვა; მხოლოდ ფოკუსის PASS შეხების პირობას არ ხურავს.
2. **[შენიშვნა — დამატებითი მობილური overflow]** ველის სიის/ბარათის ფარგლებს გარეთ დარჩენილია root overflow ორივე თემაში: ამზომველის მთავარი `/` — 390px-ზე **378/375**, 360px-ზე **378/345**; საველე მენეჯერის `/preqc` — **457/375**, **457/345**. QC მენეჯერის `/distribution` — **534/375**, **534/345**; კოორდინატორის `/checked` — 360px-ზე **366/345**. წყვილი = `scrollWidth/clientWidth`, არა viewport-ის სიგანე. ეს დაკვირვებები ახალ რეგრესიებად baseline შედარების გარეშე არ ცხადდება; სხვა ცვლილებებთან ერთად merge/deploy-ის რისკად რჩება და lead/UI-მ უნდა განსაზღვროს შესაბამისი ამოცანა.

### კონტრასტის მეთოდი და შეზღუდვები

საბოლოო კონტრასტის matrix მოიცავს ბრიფის 9 მიმდინარე ზედაპირს: QC მთავარი, `/qc`, `/qc?tab=sent`, `/qc/requests`, ხილული ბარათი, ველის სია, `/stats`, `/login`, `/about`; შესაბამისი ნებადართული როლებით, 3 ზომითა და ორივე თემით — **54 გაზომვა**. ტექსტისა და ეფექტური solid background-ის ფერები აღებულია computed CSS-იდან; CSS Color 4/color-mix გადაყვანილია ბრაუზერის canvas-ით sRGB-ში, alpha ფენები კომპოზიტდება, ratio ითვლება WCAG relative luminance-ით. გაზომვა ხდება CSS გადასვლებისთვის შეზღუდული 650ms ლოდინის შემდეგ. დახურული `details`, დამალული ტექსტი და გამორთული კონტროლები შეფასებიდან გამორიცხულია.
