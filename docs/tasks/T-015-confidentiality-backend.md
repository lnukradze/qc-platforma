### შესრულების რიგი

1. **ერთი საერთო წესი — `app/services/anon.py`.** შექმენი `actor_name(viewer_role, user, actor_role) -> str`: თუ `viewer_role in D.FIELD_ROLES` და `actor_role in D.QC_ROLES`, დააბრუნე `D.QC_ANON_LABEL`; სხვა შემთხვევაში — მომხმარებლის სრული სახელი. ადმინი QC მხარესაც მოწმდება. როლის დასადგენად გამოიყენე კონკრეტული მოქმედების `actor_role`, არა მხოლოდ მომხმარებლის მინიჭებული როლების სია: მრავალროლიანი მომხმარებლის ველის მოქმედება ველის მოქმედებად უნდა დარჩეს. დაკარგული ავტორისთვის მოარგე უსაფრთხო ცარიელი მნიშვნელობა არსებულ გამოჩენას; QC მოქმედებაზე სახელი არ გაჟონოს. ORM-ში `full_name` არ შეცვალო და ბაზაში ანონიმური სახელი არ ჩაწერო.

2. **შაბლონის კონტრაქტი — `app/routes/common.py:render()`.** თითო მოთხოვნის კონტექსტში ჩასვი `actor_name(user, actor_role)` callable, რომელიც სერვისის ფუნქციას იძახებს მიმდინარე `ctx.role`-ით. არ გამოიყენო გლობალურ Jinja გარემოში შენახული მნახველი ან საერთო mutable მდგომარეობა: პარალელურ სესიებს ერთმანეთის როლი არ უნდა გადაედოს. ძველი context გასაღებები და პასუხის სტატუსი შეინარჩუნე. T-014/T-016 ამ callable-ს გამოიყენებენ უშუალოდ შაბლონებში.

3. **ოქმების API — `app/routes/api.py:_item_json()`, `items()`, `item()`.** სერიალიზაციას მიაწოდე აქტიური მნახველის როლი. ველის ორივე როლზე `operator` გასაღები საერთოდ გამოტოვე როგორც სიაში, ისე დეტალში; `null` ან ანონიმური მნიშვნელობა ამ მოთხოვნას არ ასრულებს. QC მხარეს არსებული მონაცემი შეინარჩუნე. `items()`-იდან მოხსენი კოორდინატორის სპეციალური 403 და გამოიყენე უკვე არსებული `scope.items_query(ctx)`: კოორდინატორზე ის `first_sent_at IS NOT NULL`-ს ამატებს. არ ჩაანაცვლო მოთხოვნა შეუზღუდავი `select(QcItem)`-ით. დეტალის `scope.can_view()` და ისტორიის `scope.event_filter()` შეინარჩუნე; სიის ფილტრები და გვერდებად დაყოფა არ დააზიანო.
