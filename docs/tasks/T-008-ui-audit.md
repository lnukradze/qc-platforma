## 1. ბრიფი — lead

**მიზანი:** ui-ის ზონის აუდიტი შიგნიდან — რა არის შესაცვლელი ან დასახვეწი შაბლონებში, CSS-სა და JS-ში, და სად არ მუშაობს
ინტერფეისი (ღილაკი, ფორმა, HTMX ქმედება). ვიზუალურ აუდიტს „იზოხაზის“ მიხედვით qa აკეთებს (T-004) — აქ არ მეორდება.
მხოლოდ ანგარიში — გასწორება ეტაპი 2-ში.

**სად:** სერვერი პორტზე 8202, `data\`-ის ასლით. ანგარიშში პირადი მონაცემი არა (`docs/reports/README.md` → 🔐).
T-004-ის ანგარიში — `git show origin/main:docs/tasks/T-004-design-audit.md` (qa მას ჯერ ატვირთავს).

**შედის:**
1. **T-004-ის პასუხი:** qa-ს ყოველ აღმოჩენასა და შემოთავაზებულ ამოცანაზე — ეთანხმები / არ ეთანხმები (რატომ), ზომა (S/M/L),
   სჭირდება თუ არა backend-ის ახალი მონაცემი (კონტრაქტი).
2. **შაბლონები** (`app/templates/`): განმეორებადი მარკაპი, რომელიც `_macros.html`-ში უნდა იყოს; `style="…"` და hex ფერი;
   `|safe`; რიცხვი `|num`-ის, ოქმის# / თარიღი mono-ს გარეშე; ცარიელი / იტვირთება / შეცდომა მდგომარეობები; ბმული ან `hx-get`/`hx-post`
   მისამართზე, რომელიც არ არსებობს; ფორმები — label, required, ტელეფონზე `inputmode`; წარწერები `domain.py`-ის ტერმინებს ემთხვევა.
3. **CSS და JS** (`app/static/css/app.css`, `app/static/js/`): გამოუყენებელი ან გაორებული წესი; ტოკენის ნაცვლად ხელით ჩაწერილი მნიშვნელობა;
   მუქი თემის გამოტოვებული ადგილები; JS — კონსოლის შეცდომა, HTMX შეცდომის დამუშავება (`htmx:responseError`), CSRF HTMX მოთხოვნაზე,
   გლობალური ცვლადები, მეხსიერების გაჟონვა (presence). ბრაუზერების თავსებადობა — T-005, აქ არა.
4. **ინტერფეისში შემოწმება** (პორტი 8202): ყოველი როლით მთავარი ქმედებები ბოლომდე — ღილაკი რეაგირებს, შედეგი ჩანს,
   შეცდომისას შეტყობინება გასაგებია; კლავიატურა და `Ctrl+K`; 1366px და 390px.
5. **ხელმისაწვდომობა:** ფოკუსი, `aria`, კონტრასტი (ღია / მუქი), ქართული ტექსტი არ იჭრება.

**არ შედის:** კოდის ცვლილება; ახალი დიზაინის შემოთავაზება; Python-ის ლოგიკა (ეჭვი backend-ზე → აღმოჩენა ზონით „backend“).

**ფაილები (ზონა):** მხოლოდ `docs/reports/T-008-ui-audit.md` (ამ ამოცანისთვის ნებადართული გამონაკლისი `docs/`-ში).
