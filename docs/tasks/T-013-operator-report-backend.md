## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილება (`docs/OPEN_QUESTIONS.md`, „ოპერატორების რეპორტი“, 2026-10-26) და მისი Excel-ის ორი ნიმუში, რომლითაც QC მენეჯერი
ხელმძღვანელობას აბარებს რეპორტს. პლატფორმამ იგივე უნდა დათვალოს ავტომატურად; ხელით — მხოლოდ შესწორება და სტატუსები.
ინტერფეისი: მთავარი გვერდი — T-014; რეპორტის გვერდი — T-018.

**წესები (ნიმუშზე გადამოწმებულია):**
- **დღე** — მხოლოდ **ორშ–პარ**; შაბათი და კვირა რეპორტში არ ჩანს (არც სვეტად, არც საშუალოში).
- **გავლილი დღეში** = პირველი გაგზავნა (`first_sent_at`, D) იმ დღეს — იგივე წესი, რაც `stats.operator_daily`-ში;
  `ჯამი = დათვლილი + Σ delta` (გაუუქმებელი `D.ADJ_COUNT`).
- **სტატუსი დღეზე** — `D.ADJ_STATUS_KINDS` (შვებულება, ბიულეტინი, სამსახურეობრივი დავალება, დეიოფი): უჯრაში წარწერა რიცხვის ნაცვლად (თუ ჯამი 0-ია).
- **სამუშაო დღე** = ორშ–პარ, სადაც ჯამი > 0. **საშუალო** = Σ ჯამი / სამუშაო დღეები (0-იანი და სტატუსიანი დღე არ ითვლება), მთელ რიცხვამდე დამრგვალებული.
  ნიმუში: 0, 0, 37, 49, 39 → 125 / 3 → **42**.
- **კვირის უჯრა** („კვირები“) = იმ კვირის საშუალო; თუ კვირაში სამუშაო დღე არ არის და სტატუსი აქვს — სტატუსის წარწერა
  (რამდენიმეა → ყველაზე ხშირი; თანაბარია → `D.ADJ_STATUS_KINDS`-ის რიგით); არც ერთი → „—“.
- **„საშუალო 01.07-დან“** — `D.REPORT_SINCE`-დან დღემდე, იგივე წესით.
- **სულ შემოწმებული** — ოპერატორის ყველა ოქმი `first_sent_at`-ით (ძველი გადმოტანილიც), პერიოდის გარეშე.
- **ხარვეზი %** (ოპერატორის შეცდომა) = (`qc_error` — „ველი მართალია“ + QC მენეჯერის შეფასების შენიშვნები `D.ERROR_MARKS`) / სულ შემოწმებული × 100, 1 ათწილადი.
  იგივე, რაც `stats.restricted`-ის `errors_total` (არ გააორმაგო — ერთი ფუნქცია).
- **სტატუსების ცხრილი დღეებით** — თითო ორშ–პარ: უარყოფითი / დადებითი (+დაზუსტება) / რეკომენდაცია / სულ — `stats`-ის კატეგორიებით (`_cat_exprs`), D-ის დღით;
  ბოლოს — სულ (მთელი პერიოდი) და წილი %.

**შედის:**
1. სერვისი (`app/services/`, მაგ. `oprep.py`): `day_report(db, day)`, `week_report(db, week_start)`, `weeks_report(db, from_week, to_week)` — ერთი-ორი SQL ყოველზე, არა N+1.
   ოპერატორები — ყველა, ვისაც QC ოპერატორის როლი აქვს ან პერიოდში ოქმი / შესწორება.
2. **გვერდი** `GET /reports/operators` (QC მენეჯერი, ადმინი): `?tab=week&week=YYYY-MM-DD` (ნაგულისხმევი — მიმდინარე კვირა) და
   `?tab=weeks&from=YYYY-MM-DD&to=YYYY-MM-DD` (ნაგულისხმევი — ბოლო `D.REPORT_WEEKS_DEFAULT` კვირა, მიმდინარის ჩათვლით). შაბლონი — T-018.
3. **შესწორება** — `POST /reports/operators/adjust` (QC მენეჯერი, ადმინი; CSRF): `operator_id`, `day`, `kind` ∈ `D.REPORT_ADJ_KINDS` (კოდში შემოწმება), `delta`, `note` (სავალდებულო);
   გადატანა: `to_operator_id` → ორი ჩანაწერი (−N / +N, ერთი შენიშვნით); სტატუსი პერიოდზე: `day` და `day_to` → თითო ორშ–პარ დღეზე ჩანაწერი.
   `POST /reports/operators/adjust/{id}/revoke` — გაუქმება (`revoked_by`, `revoked_at`; არ იშლება). ორივე — `audit()`-ში. დაბრუნება `back`-ით (T-010, S-02 — მხოლოდ შიდა მისამართი).
4. **Excel** — `GET /reports/operators/export.xlsx?week=…` (ან `from` / `to`): ფურცლები **„კვირა“** (ოპერატორი × ორშ–პარ, საშუალო 01.07-დან, სულ შემოწმებული, ხარვეზი %;
   ქვემოთ — სტატუსების ცხრილი დღეებით), **„კვირები“** (ოპერატორი × კვირები; სათაურში თარიღები „28.09–02.10“), **„შესწორებები“** (ვინ, როდის, რა).
   ტექსტის უჯრა ფორმულად არ აღიქმება (T-010, S-11).
5. **მთავარი გვერდი** (`routes/pages.py`, QC მენეჯერი და ადმინი): `rep_day` (დღე) და `rep_week` (მიმდინარე კვირა — გაშლისთვის); **„ბოლო მოქმედებები“ — 10** (ყველა როლი).
6. ძველი სქემა: თუ `report_adjustments` უკვე შექმნილია ძველი CHECK-ით (`ck_report_adj_kind`) **და ცარიელია** — გაშვებისას გადაიქმნას (ერთჯერადი, უსაფრთხო).
   ჩანაწერები თუ აქვს — შეჩერდი და lead-ს უთხარი.
7. `scripts/build_demo_db.py` — დემო შესწორებები და სტატუსები (შვებულება მთელ კვირაზე, ბიულეტინი, სამსახურეობრივი დავალება, დეიოფი, გადატანა).
8. ვინ ხედავს: მხოლოდ QC მენეჯერი და ადმინი (`require`) — გვერდი, Excel, შესწორება.

**არ შედის:** შაბლონები (T-014, T-018); `/stats` არ იცვლება; `models.py` / `domain.py` (lead-მა უკვე: `ReportAdjustment`, `D.REPORT_SINCE`, `D.REPORT_WEEKS_DEFAULT`, `D.ADJ_*`, `D.ADJ_STATUS_KINDS`).

**ფაილები (ზონა):** `app/services/` (ახალი), `app/routes/pages.py`, ახალი route ფაილი `app/routes/`-ში, `app/main.py`, `app/db.py` (პუნქტი 6), `scripts/build_demo_db.py`.

**კონტრაქტი (backend ↔ ui):**

უჯრა `cell` = `{counted: int, adjusted: int, total: int, status: str | None, status_label: str | None, manual: bool}` (`manual` — ხელით შესწორებულია).

| ცვლადი | სად | შინაარსი |
|---|---|---|
| `rep_day` | `home.html` | `{day, rows: [{operator_id, name, cell}], total}` |
| `rep_week` | `home.html`, რეპორტის გვერდი | `{week_start, days: [date ×5], rows: [{operator_id, name, cells: [cell ×5], avg_since: int\|None, total_all: int, error_pct: float\|None}], by_status: [{key, label, per_day: [int ×5], total_all, share_pct}], day_totals: [int ×5], grand_total_all, prev_week, next_week}` |
| `rep_weeks` | რეპორტის გვერდი | `{weeks: [{start, end, label}], rows: [{operator_id, name, cells: [{avg: int\|None, status, status_label}]}], from, to}` |
| `rep_adjustments` | ორივე | `[{id, operator, day, kind, kind_label, delta, note, by, at, revoked}]` — ნაჩვენები პერიოდის |
| `rep_operators` | ფორმა | `[(id, name)]` |
| `tab` | რეპორტის გვერდი | `"week"` / `"weeks"` |
| `recent` | `home.html` | ბოლო 10 მოვლენა |

ფორმის ველები: `operator_id`, `to_operator_id`, `day`, `day_to`, `kind`, `delta`, `note`, `back`.

**დასრულების პირობა** (ტესტირებადი):
1. pytest (ახალი `tests/test_oprep.py` — ნებადართული გამონაკლისი), გამოგონილი ოქმებით: 0, 0, 37, 49, 39 → საშუალო 42; სტატუსიანი დღე საშუალოში არ ითვლება;
   სამუშაო დღის გარეშე სტატუსიან კვირაზე — სტატუსის წარწერა; შაბათის ოქმი დღეებში და საშუალოში არ ჩანს, „სულ შემოწმებულში“ — ჩანს;
   ხარვეზი % = (`qc_error` + შეფასების შენიშვნები) / სულ; `+3` / `−2` ჯამში აისახება; გაუქმებული — არა; გადატანა — ორი ჩანაწერი; პერიოდის სტატუსი — თითო ორშ–პარ დღეზე.
2. სტატუსების ცხრილის „სულ“ თითო დღეზე = უარყოფითი + დადებითი + რეკომენდაცია; დადებითი = იგივე რიცხვი, რაც `/stats`-ში იმავე დღეზე.
3. ოპერატორი / საველე / კოორდინატორი / სამსახურის უფროსი → გვერდი, Excel, შესწორება → 403; CSRF-ის გარეშე → 403.
4. Excel: სამი ფურცელი, სტრუქტურა ზემოთ აღწერილის მიხედვით.
5. დემო ბაზაზე `--items 45000`-ით: მთავარი (QC მენეჯერი) და რეპორტის გვერდი — თითო < 1 წმ.
6. `pytest -q` გადის; `smoke_pages.py` დემო ბაზაზე — 0 შეცდომა.
