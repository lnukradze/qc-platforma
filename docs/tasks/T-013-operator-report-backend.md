## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილება (`docs/OPEN_QUESTIONS.md`, „ოპერატორების რეპორტი“, 2026-10-26): QC მენეჯერი მთავარ გვერდზე ნათლად ხედავს,
**ყველა ოპერატორმა დღეს რამდენი გაიარა**; გაშლით — **სრულ კვირას** (ორშ–კვ) ხელმძღვანელობის რეპორტისთვის. რეპორტში შეუძლია ხელით შესწორება:
ერთს მოაკლოს და მეორეს დაუწეროს, კონკრეტულ დღეს დეიოფი ჩაუწეროს, მთელ კვირას შვებულება. ინტერფეისი — T-014 (ui).

**შედის:**
1. **დათვლა:** „გავლილი“ = პირველი გაგზავნა (`first_sent_at`, D) იმ დღეს — იგივე წესი, რაც `stats.operator_daily`-ში (დაზუსტების კითხვაც ითვლება).
   დღე = 00:00–24:00. შესწორება ემატება: `ჯამი = დათვლილი + Σ delta` (მხოლოდ გაუუქმებელი `ReportAdjustment`, `kind == D.ADJ_COUNT`).
   `D.ADJ_DAY_OFF` / `D.ADJ_VACATION` — დღის ნიშანი (რაოდენობას არ ცვლის).
2. **სერვისი** (`app/services/`-ში, მაგ. `oprep.py`): `day_report(db, day)` და `week_report(db, week_start)` — ყველა აქტიური ოპერატორი,
   ვისაც იმ პერიოდში ოქმი აქვს ან შესწორება (და ყველა QC ოპერატორის როლის მქონე). ერთი-ორი SQL მოთხოვნა, არა N+1.
3. **შესწორება** — `POST /reports/operators/adjust` (QC მენეჯერი, ადმინი; CSRF): `operator_id`, `day`, `kind`, `delta`, `note` (სავალდებულო);
   გადატანა: `to_operator_id` → ორი ჩანაწერი (−N პირველს, +N მეორეს, ერთი შენიშვნით); შვებულება: `day` და `day_to` → თითო დღეზე ჩანაწერი.
   `POST /reports/operators/adjust/{id}/revoke` — გაუქმება (`revoked_by`, `revoked_at`; ჩანაწერი არ იშლება). ორივე — `audit()`-ში.
4. **Excel** — `GET /reports/operators/export.xlsx?week=YYYY-MM-DD`: ოპერატორი × 7 დღე + ჯამი; დეიოფი / შვებულება წარწერით; ქვემოთ — შესწორებების სია (ვინ, როდის, რა).
   Excel-ის ტექსტის უჯრები — ფორმულად არ აღიქმება (T-010, S-11).
5. **მთავარი გვერდი** (`routes/pages.py`, QC მენეჯერი და ადმინი): კონტრაქტის ცვლადები (ქვემოთ); `?week=` — სხვა კვირა.
   **„ბოლო მოქმედებები“ — ბოლო 10** (ყველა როლი; ახლა 8).
6. ვინ ხედავს: მხოლოდ QC მენეჯერი და ადმინი (`require`). კოორდინატორი და სამსახურის უფროსი — არა (ოპერატორების სტატისტიკა მათ არ უჩანს).

**არ შედის:** შაბლონები (T-014); `models.py` / `domain.py` — lead-მა უკვე დაამატა `ReportAdjustment`, `D.ADJ_*`, `D.REPORT_ADJ_KINDS`; ხარვეზების სტატისტიკა (`/stats`) არ იცვლება.

**ფაილები (ზონა):** `app/services/` (ახალი), `app/routes/pages.py`, ახალი route ფაილი `app/routes/`-ში, `app/main.py` (router), `scripts/build_demo_db.py` (რამდენიმე დემო შესწორება).

**კონტრაქტი (backend ↔ ui)** — `home.html`-ს QC მენეჯერსა და ადმინზე:

| ცვლადი | ტიპი | შინაარსი |
|---|---|---|
| `rep.day` | date | დღევანდელი დღე |
| `rep.rows` | list[dict] | `{operator_id, name, counted, adjusted, total, off}` — `off`: `None` / `"day_off"` / `"vacation"` |
| `rep.day_total` | int | დღის ჯამი |
| `rep.week_start`, `rep.days` | date, list[date ×7] | ორშაბათი; ორშ–კვ |
| `rep.week_rows` | list[dict] | `{operator_id, name, cells: [{counted, adjusted, total, off} ×7], total}` |
| `rep.week_totals` | list[int ×7] | დღეების ჯამი |
| `rep.prev_week`, `rep.next_week` | str (YYYY-MM-DD) / None | ნავიგაცია (`next` — None, თუ მომავალია) |
| `rep.adjustments` | list[dict] | კვირის შესწორებები: `{id, operator, day, kind, kind_label, delta, note, by, at, revoked}` |
| `rep.operators` | list[(id, name)] | ფორმის ჩამოშლისთვის |
| `recent` | list[QcEvent] | ბოლო 10 |

ფორმის ველები: `operator_id`, `to_operator_id` (არასავალდებულო), `day`, `day_to` (შვებულება), `kind` ∈ `D.REPORT_ADJ_KINDS`, `delta` (int), `note`, `week` (დასაბრუნებლად).
