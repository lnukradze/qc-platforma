## 1. ბრიფი — lead

**მიზანი (P0):** წესი — „ერთ კოდზე ერთი პასუხი; პირველი პასუხი ითვლება“ (`docs/OPEN_QUESTIONS.md`, „ორი ამზომველი ერთად“). T-009-მა (E-06) დაადასტურა,
რომ ორი ერთდროული პასუხი **ორივე** ინახება: ვერსიის შემოწმება (`workflow.py:235`) წაკითხვასა და ჩაწერას შორის ატომური არ არის.
ერთიანი სურათი — `docs/reports/STAGE-1-SUMMARY.md`, P0-2.

**შედის:**
1. **ატომური ვერსია** — ყოველი ქმედება, რომელიც მდგომარეობას / სტატუსს ცვლის: ჩაწერა ერთი `UPDATE qc_items … WHERE id = :id AND version = :v` (ან SQLAlchemy
   `version_id_col`), შეცვლილი მწკრივი 0 → `ConflictError` (არსებული შეტყობინებით „ამ ოქმზე პასუხი უკვე გაგზავნა …“). SQLite-ზეც და PostgreSQL-ზეც.
   `version` ფორმაში **სავალდებულოა** მდგომარეობის შემცვლელ ქმედებებზე (T-010, S-09).
2. **კომენტარი** — B-11: ორჯერ დაჭერა / ორი ჩანართი → ერთი კომენტარი და ერთი მეილი (ერთჯერადი token ფორმაში ან „იგივე ტექსტი + ავტორი ბოლო 60 წმ-ში“ → არ იქმნება).
   B-12: კომენტარი და QC მენეჯერის შეფასება `version`-ს **არ** ზრდის (კონფლიქტი მხოლოდ მდგომარეობის / სტატუსის ცვლილებაზე).
3. რეგრესიის ტესტი **ნამდვილი პარალელით** (ორი ნაკადი / ორი სესია, ერთი საწყისი `version`, ერთდროული POST) — 20 გამეორება, ყოველთვის ზუსტად ერთი წარმატება.

**არ შედის:** შაბლონები (ui-ს ფორმის ველი, თუ token სჭირდება — „სხვა როლებისგან სჭირდება“ commit-ში); სხვა სამუშაო წესები — T-021.

**ფაილები (ზონა):** `app/workflow.py`, `app/routes/items.py`, `app/services/notify.py`, `tests/test_concurrency.py` (ახალი — ნებადართული გამონაკლისი).
