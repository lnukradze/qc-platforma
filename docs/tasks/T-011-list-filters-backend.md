## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილება (`docs/OPEN_QUESTIONS.md`, „სიების ფილტრები“, „ერთად გაგზავნა“, 2026-10-26):
ფილტრის ქცევა ერთნაირია ყველა სიაში — QC სია (`/qc`), ველის სია (`/field`), არ დათანხმებულები (`/qc/disagreements`), გავლილი (`/checked`).
ახლა თითო route-ს თავისი `_filters` აქვს და ერთმანეთისგან განსხვავდება (მაგ. `/field` თარიღს გაგზავნით ფილტრავს). ერთი სერვისი — ერთი წესი.
ინტერფეისი — T-012 (ui), ამ კონტრაქტით.

**შედის:**
1. ახალი `app/services/listfilter.py`: პარამეტრების წაკითხვა და გასწორება, `select`-ზე გამოყენება, ფილტრის სიების (მენეჯერები, ამზომველები, ოპერატორები) მომზადება.
   ოთხივე route მას იყენებს; ძველი `_filters` / `_d` (`routes/qc.py`, `routes/field.py`) იშლება.
2. წესები:
   - **თარიღი** — `QcItem.drawing_date` (ნახაზის შეტანა) ყველა სიაში. `date_from` ჩათვლით (00:00-დან), `date_to` — **არა** (00:00-მდე):
     01.01–02.01 → მხოლოდ 01.01-ის ოქმები; `date_from == date_to` ან `date_from > date_to` → შედეგი ცარიელია და `flt.empty_range = True`.
     მხოლოდ ერთი თარიღი → ცალმხრივი პირობა.
   - **ზონა** — რამდენიმე, მძიმით ან ჰარით (`50, 73`); ყოველი `zfill(2)`; `IN`.
   - **სექტორი** — მძიმით, **მხოლოდ თუ ზონა მითითებულია** (ზონის გარეშე იგნორდება). ემთხვევა `QcItem.sector`-ს — მიიღე როგორც `39`, ისე `43.39`.
   - **მენეჯერი** და **ამზომველი** — id (ციფრები) ან ტექსტი (სახელის ნაწილი, `LIKE`). მენეჯერის არჩევისას ამზომველების სია ვიწროვდება მის გუნდზე.
   - **ოპერატორი** — id; **ველის როლებისთვის იგნორდება და სია ცარიელია** (კონტროლი ანონიმურია).
   - **სტატუსი** (`verdict`) — QC სიის „გასავლელში“ იგნორდება (`flt.show_status = False`).
   - **ველის სტატუსი** (`response`), **სახე** (`kind`), **ოქმის#** (`protocol`), **საკ. კოდი** (`cad`) — როგორც ახლა.
   - **გვერდის ზომა** (`per`) — `D.PAGE_SIZE_MIN`..`D.PAGE_SIZE_MAX`, ნაგულისხმევი `D.PAGE_SIZE_DEFAULT`; ყველა ოთხ სიაში (`paginate`-ს გადაეცემა).
   - ოპერატორის „გასავლელი“ — ძველი შეზღუდვა რჩება (`restricted_filters`: მხოლოდ ოქმის# და საკ. კოდი), `flt.limited = True`.
   - **ველის სია** (ლუკა, 2026-10-27, T-007 Q-02): საბოლოოდ დადასტურებული (`closed`) ოქმი ნაგულისხმევ სიაში არ ჩანს; ჩანს, როცა ფილტრი
     (`state=closed` ან სტატუსი / თარიღი) ან ძებნა (ოქმის# / საკ. კოდი) მითითებულია. რომელი ოქმი ჩანს ველს საერთოდ — T-021 (`scope.field_visible`).
3. `GET /api/filters/surveyors?manager=<id>` → `[{"id": 1, "name": "…"}]` — მენეჯერის გუნდის ამზომველები (ui-ის ჩამოშლისთვის).
   QC როლები, ადმინი, კოორდინატორი — ნებისმიერი მენეჯერი; საველე მენეჯერი — მხოლოდ საკუთარი გუნდი; სხვა — `[]`. `scope`-ის წესით, CSRF არ სჭირდება (GET).
4. ~~`/qc/bulk-send` route იშლება~~ — გადავიდა T-019-ში (lead, 2026-10-27).

**არ შედის:** შაბლონები და JS (T-012); სიების დალაგება და ჩანართები; `models.py` / `domain.py` (lead-მა უკვე დაამატა `PAGE_SIZE_*`).

**ფაილები (ზონა):** `app/services/listfilter.py` (ახალი), `app/routes/qc.py`, `app/routes/field.py`, `app/routes/api.py` (ან ახალი route ფაილი `app/routes/`-ში).

**კონტრაქტი (backend ↔ ui):** ოთხივე სიის შაბლონს გადაეცემა `flt` (dict):

| გასაღები | ტიპი | შინაარსი |
|---|---|---|
| `values` | dict[str, str] | გასწორებული პარამეტრები: `protocol, cad, date_from, date_to, zone, sector, manager, surveyor, operator, verdict, response, kind` |
| `managers` | list[(id, name)] | მენეჯერები, ვისი ოქმებიც ამ სიაში ჩანს |
| `surveyors` | list[(id, name)] | ამზომველები (მენეჯერით შევიწროებული, თუ არჩეულია) |
| `operators` | list[(id, name)] | ოპერატორები; ველის როლებზე `[]` |
| `show_operator` | bool | ოპერატორის ფილტრი ჩანს? (ველის როლებზე `False`) |
| `show_status` | bool | სტატუსის ფილტრი ჩანს? (QC „გასავლელში“ `False`) |
| `limited` | bool | ოპერატორის „გასავლელი“ — მხოლოდ ოქმის# და საკ. კოდი |
| `per` | int | გვერდის ზომა (10–30) |
| `empty_range` | bool | თარიღის დიაპაზონი ცარიელია (from ≥ to) |

query-ს სახელები ზემოთაა (`per`, `page` — დამატებით). `qs(...)` ფუნქცია `per`-ს ინარჩუნებს.

**დასრულების პირობა** (ტესტირებადი):
1. pytest-ში (ახალი ფაილი `tests/test_listfilter.py` — ამ ამოცანისთვის ნებადართული გამონაკლისი) გამოგონილი ოქმებით: 01.01–02.01 → მხოლოდ 01.01; 01.01–01.01 → 0 და `empty_range`;
   `zone=50, 73` → ორივე ზონა; `sector=39` ზონის გარეშე → იგნორდება, ზონით → ფილტრავს; `operator=<id>` ამზომველის როლით → იგნორდება.
2. ოთხივე სიაში იგივე პარამეტრი ერთნაირ შედეგს იძლევა (ერთი ოქმი სამივე ხილულ სიაში — ერთნაირად ფილტრდება).
