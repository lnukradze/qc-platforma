- **ბ — T-011-ის ჩაბარების შემდეგ** (კონტრაქტი `flt`): პუნქტები 1–3.

## 2. პრომპტი შემსრულებლისთვის — qa (Codex)

> ბრიფს არ ცვლის — მხოლოდ „როგორ“-ს ამატებს. დასრულების პირობა ნაწილი 1-იდან სიტყვასიტყვით.

### ნაწილი ა — პრომპტი UI შემსრულებლისთვის

**სამუშაო ვერსია, დასადასტურებელი (2026-10-27).** ეს პრომპტი ეხება მხოლოდ ნაწილი ა-ს; ნაწილი ბ-ს დაწყებას და მთელი T-012-ის ჩაბარებას არ ნიშნავს. UI Claude-ს წინასწარი ანალიზი უკვე მზად აქვს — გამოიყენე თავისი არსებული ანალიზი და შეადარე ქვემოთ მოცემულ ფაილებსა და საზღვრებს; თავიდან იმავე ანალიზის მომზადება საჭირო არ არის. ანალიზის ტექსტი ამ დოკუმენტს არ ახლავს, ამიტომ მის დაუდასტურებელ დასკვნებს შეთანხმებულ მოთხოვნად ნუ ჩათვლი.

შენ ხარ ui. მიზანია არსებული სიებიდან ჯგუფური მონიშვნის, დაფის და header-ის გლობალური ძებნის ამოღება და წარწერებისა და QC „გასავლელის“ სვეტების გამარტივება. ნაწილი ა მუშაობს ახლანდელი backend-ის ცვლადებით; `flt` კონტრაქტი და ახალი ფილტრები T-011-ის ჩაბარების შემდეგ, ნაწილი ბ-ში გამოიყენება.

### საზღვრები და უსაფრთხო გარემო

- წაიკითხე `AGENTS.md`, `docs/team/roles/ui.md`, `docs/team/SALOME.md`, `DESIGN.md` და ამოცანის ნაწილი 1. სამუშაო ბრენჩია `ui/T-012-lists`; თუ ის უკვე არსებობს და ანალიზი/სამუშაო აქვს, შეინარჩუნე. main-ში არ იმუშაო და არ ატვირთო. ამ პრომპტის მომზადების ეტაპზე commit/push არ კეთდება; შემსრულებლის შემდგომი ჩაბარება ცალკე ავტორიზებულ სამუშაოს ეკუთვნის.
- ნაწილი ა-ს **დადასტურებული მოცულობაა ბრიფის 4–7**: checkbox/bulk/board-ის ამოღება, წარწერები, QC „გასავლელის“ სტატუსისა და კოდების სვეტების დამალვა, header-ის `cmdk`-ის წაშლა. როლის გადამრთველი რჩება.
- **ნაწილი ბ-ში რჩება 1–3:** ერთიანი ფილტრის მაკრო და ორი ხაზის განლაგება, ზონა/სექტორის ახალი ქცევა, თარიღების ახალი კონტრაქტი, `per` 10–30, ჩაწერადი მენეჯერი/ამზომველი და მათი API, `flt.show_operator` / `flt.show_status` / `flt.limited` / `flt.empty_range`, ველის სიის ანონიმურობის სრული პუნქტი 3. ნაწილი ა-ში ესენი არ მოიგონო და `flt` არ მოითხოვო. არსებული ველის სიის კონფიდენციალურობა არ გააუარესო; აღმოჩენილი გაჟონვა ცალკე აღწერე T-015/ნაწილი ბ-ს დამოკიდებულებით.

- ნაწილი ა-ს კოდი: `app/templates/base.html`, `app/templates/qc/list.html`, `qc/_table.html`, `qc/disputes.html`, `qc/checked.html`, `app/templates/field/list.html`, `field/_table.html`, `app/static/js/app.js`, საჭიროებისამებრ `app/static/css/app.css`. სხვა შაბლონები შეეხე მხოლოდ მაშინ, თუ იმავე მოსაშლელი მექანიზმის ფაქტობრივი გამოყენება იპოვე და ეს ბრიფის 4–7-ში ჯდება. Python, backend endpoint-ები, საერთო კონტრაქტები, ბარათი და მთავარი არ შეცვალო. ახალი ფილტრის მაკრო ნაწილი ა-ს არ სჭირდება.

### განხორციელების ნაბიჯები

1. **QC ცხრილი — `qc/_table.html`.** მთლიანად ამოიღე `#bulk-form` POST wrapper, `/qc/bulk-send`-ზე ფორმა, ამ ფორმის `back` ველი, `.check-all`, მწკრივების `input[name=ids]`, მონიშვნის უჯრები და `#bulkbar`/`#bulk-n`. მხოლოდ CSS-ით დამალვა საკმარისი არ არის. ცხრილი, ლეგენდა, რაოდენობა, empty state და `pager(...)` დარჩეს გამართულ DOM-ში. ცალკეული ოქმის გახსნა და „შემდეგი ოქმი“ შეინარჩუნე. backend-ის bulk endpoint ამ ამოცანაში არ იცვლება.

### ლუკას გადაწყვეტილებას მოითხოვს

1. **ტესტების კოორდინაცია:** დაადასტუროს `tests/test_ui.py`-ის განახლების QA/lead გზა და UI ცვლილებასთან ჩართვის რიგი. განახლებამდე სრული `pytest -q`-ის წარმატება მოსალოდნელი არ არის. UI-მ უნდა წარმოადგინოს რეალური შედეგი, ზუსტად მიუთითოს ძველ მოთხოვნებთან კონფლიქტი; QA ტესტებისა და სრული შემოწმების გარეშე ნაწილი ა ჩაბარებულად არ გამოცხადდეს.
2. **პუნქტი 8:** „ა — პუნქტები 4–7“ პუნქტ 8-ს არც ა-ს და არც ბ-ს ცხადად არ ანაწილებს. ლუკამ განსაზღვროს `inputmode="decimal"` ამ ეტაპზე კეთდება თუ შემდეგში; ასევე U-24-ის ჩანართების სემანტიკის მფლობელი — T-012 თუ T-025. T-025 უშვებს როგორც სწორ tabs მოდელს, ისე უბრალო ნავიგაციას; T-012 ითხოვს `role="tab"`/`aria-selected`. დაუდასტურებლად მოდელი არ აირჩიო და მხოლოდ ARIA ატრიბუტებით არასრული tabs ნუ შექმნი.
3. **„გასავლელის“ სტატუსის ფილტრი:** პუნქტი 6 ნაწილი ა-ში ასახელებს ორ სვეტს, მაგრამ დასრულების პირობა 7 ფილტრის დამალვასაც ითხოვს; ნაწილი ბ-ში ამას `flt.show_status` მართავს. ლუკამ დაადასტუროს, ნაწილი ა-ში დაემატოს თუ არა არსებული `tab != 'todo'` პირობით UI ფილტრის დამალვა. დადასტურების შემდეგ ცვლილება მხოლოდ ხილვადობის შაბლონს ეხება, query-ის სერვერული ქცევა T-011-ს რჩება.

ეს კითხვები არ ცვლის ბრიფს: დაუდასტურებელი პუნქტები აღირიცხება როგორც გადასაწყვეტი და არა თვითნებურად მიღებული გამონაკლისი. ნაწილის ა-ს უპირობო სამუშაო გაგრძელდეს; შესაბამისი სადავო ცვლილება პასუხამდე არ შესრულდეს.

### შემოწმება და ნაწილი ა-ს ანგარიში

1. ცვლილებამდე შეინახე მიზნობრივი/სრული pytest-ისა და Hallmark-ის საწყისი შედეგი, რათა ძველი პრობლემა ახალს გაემიჯნოს. გამოიყენე `QCP_PY`, ხოლო თუ არ არის დაყენებული — `.venv\Scripts\python.exe`. Python-ის ყველა გაშვებაზე `QCP_AGENT=1` იყოს. `pytest` მხოლოდ დროებით ბაზაზე გაუშვი.

```powershell
$env:QCP_AGENT = "1"
& $env:QCP_PY -m pytest -q tests/test_ui.py
& $env:QCP_PY -m pytest -q
```
