## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილებები (`docs/OPEN_QUESTIONS.md`, 2026-10-26): ფილტრის განლაგება და ქცევა ერთნაირია ყველა სიაში და ყველა როლისთვის;
ცხრილი მარტივდება. ოთხი სია: `qc/list.html`, `field/list.html`, `qc/disputes.html`, `qc/checked.html`.

**ორ ნაწილად:**
- **ა — ახლავე** (backend არ სჭირდება): პუნქტები 4–7.
- **ბ — T-011-ის ჩაბარების შემდეგ** (კონტრაქტი `flt`): პუნქტები 1–3.

**შედის:**
1. **ერთი მაკრო** ფილტრისთვის (მაგ. `_filters.html`), ოთხივე სიაში. განლაგება:
   - პირველი ხაზი: **ოქმის N · საკ. კოდი · თარიღი დან · მდე · ზონა · სექტორი**;
   - მეორე ხაზი: **მენეჯერი · ამზომველი · ოპერატორი · სტატუსი · ველის სტატუსი**;
   - „სექტორი“ — გამორთულია, სანამ ზონა ცარიელია (მინიშნებით); ზონაში — მინიშნება „მაგ. 50, 73“;
   - „ოპერატორი“ — მხოლოდ `flt.show_operator`; „სტატუსი“ — მხოლოდ `flt.show_status`; `flt.limited` — მხოლოდ ოქმის N და საკ. კოდი;
   - `flt.empty_range` → მინიშნება „„მდე“ თარიღი „დან“-ზე გვიან უნდა იყოს — 01.01–02.01 აჩვენებს 01.01-ს“;
   - **რამდენი ჩანაწერი** — არჩევანი 10–30 (`per`), ფილტრის სექციაში, ოთხივე სიაში.
2. **მენეჯერი და ამზომველი** — ჩაწერითაც და ჩამოშლითაც (`<input list>` + `<datalist>` ან მსგავსი, DESIGN.md-ის ფარგლებში);
   მენეჯერის არჩევისას ამზომველების სია განახლდება: `GET /api/filters/surveyors?manager=<id>`.
   სერვერი (T-011) ციფრებით ჩაწერილ მნიშვნელობას id-ად კითხულობს, ტექსტს — სახელად: სიიდან არჩევისას იგზავნება id, მომხმარებელს ველში ნომერი
   არ უჩანს (სახელი); ხელით ჩაწერისას — ტექსტი.
   **მენეჯერის შეცვლა** (lead, 2026-10-28): არჩეული ამზომველი ახალ სიაში თუ არ არის — ავტომატურად სუფთავდება (მოთხოვნის გაგზავნამდე).
   **URL-იდან აღდგენა:** `flt.values`-ის მნიშვნელობა არჩევანში თუ არ არის — დამატებითი მოთხოვნით სახელი **არ** მოიძებნება; ველში რჩება
   როგორც არის (ფილტრი მოქმედია და ჩანს, მომხმარებელს შეუძლია გაასუფთაოს). ჩუმად არ სუფთავდება — სია გაფილტრული იქნებოდა, ფორმა კი „ყველას“ აჩვენებდა.
3. ველის სიაში ოპერატორის სვეტი / სახელი არსად (კონტროლი ანონიმურია).
4. **checkbox-ები და დაფა** — ქრება ყველა სიიდან (`qc/_table.html`: `bulk-form`, `bulkbar`; `app.js`: bulk და board კოდი; ხედის გადამრთველი „ცხრილი / დაფა“).
5. **წარწერები** ყველა სიაში (სვეტი და ფილტრი): „ვერდიქტი“ → **„სტატუსი“**; „ნახაზი“ → **„თარიღი“**; „ველის პასუხი“ → **„ველის სტატუსი“**.
6. QC სიის **„გასავლელში“** სვეტები „სტატუსი“ და „კოდები“ არ ჩანს (ჯერ არცერთს არ აქვს).
7. **header**: ძებნის ველი („ოქმის# ან გვერდი… Ctrl K“) და მისი JS (`cmdk`) ქრება — ლუკამ დაადასტურა, საბოლოოა (ამით იხურება U-15 და U-18-ის `cmdk` ნაწილი).
   როლის გადამრთველი **რჩება**.
8. ფილტრებში საკ. კოდზე `inputmode="decimal"` (U-27); ჩანართები — `role="tab"` / `aria-selected` სწორად (U-24, თუ T-025-მდე აკეთებ).

**არ შედის:** Python-ის ლოგიკა (T-011); ოქმის ბარათი (T-016); მთავარი გვერდი (T-014); ახალი დიზაინის ელემენტები DESIGN.md-ის გარეთ.

**ფაილები (ზონა):** `app/templates/` (`base.html`, `qc/*`, `field/*`, ახალი მაკრო), `app/static/css/app.css`, `app/static/js/app.js`.

**კონტრაქტი (backend ↔ ui):** `flt` — T-011-ის ბრიფში (ცხრილი). ნაწილი ბ-მდე ძველი ცვლადებით მუშაობს.

**დასრულების პირობა** (ტესტირებადი):
1. ოთხივე სიაში ფილტრის ორი ხაზი ზუსტად ამ რიგით; 1366px-ზე ორ ხაზში ეტევა, 390px-ზე — ერთ სვეტად, ჰორიზონტალური გადაცურების გარეშე.
2. სექტორი ზონის გარეშე გამორთულია; ზონის ჩაწერისას ირთვება.
3. მენეჯერის არჩევისას ამზომველის სია იცვლება (დემო ბაზაზე: „საველე მენეჯერი ა“ → „ამზომველი 01–04“); ორივეში ჩაწერაც მუშაობს.
4. რამდენი ჩანაწერი: 10 / 20 / 30 (ან 10–30) — ცხრილი შესაბამისად; გვერდის შეცვლისას არჩევანი რჩება.
5. checkbox, დაფა, ძებნის ველი და `Ctrl K` — არსად; კონსოლი სუფთა.
6. „ვერდიქტი“, „ნახაზი“, „ველის პასუხი“ სიებში აღარ გვხვდება (`grep` შაბლონებში — მხოლოდ ბარათზე, T-016).
7. „გასავლელში“ სტატუსისა და კოდების სვეტი და სტატუსის ფილტრი არ ჩანს.
8. ველის როლით (დემო „ამზომველი 07“, „საველე მენეჯერი ა“) ოპერატორის ფილტრი და სახელი არ ჩანს.
9. `pytest -q` გადის; Hallmark — ახალი FAIL არ გაჩნდა.

**ჩაბარებისას შევამოწმებ:** ვიზუალი — 1366 / 390px, ღია / მუქი, QC ოპერატორი, QC მენეჯერი, საველე მენეჯერი, ამზომველი; უსაფრთხოება — ველზე ოპერატორის სახელი არ ჩანს.

**lead-ის გადაწყვეტილებები qa-ს კითხვებზე (2026-10-27):**
- **„გასავლელის“ სტატუსის ფილტრი** — იმალება **ნაწილი ა-ში** (`tab != 'todo'`, მხოლოდ შაბლონი; ლუკას თავდაპირველი მოთხოვნა). სერვერის ქცევა — T-011.
- **პუნქტი 8:** `inputmode` საკ. კოდზე — **ნაწილი ბ**, ფილტრის ახალ მაკროსთან; რეალურ ტელეფონზე შემოწმება — iPhone-ზე წერტილის ნაცვლად მძიმე → ჩვეულებრივი კლავიატურა.
  ჩანართების ARIA (U-24) — **T-025**, აქ არა.
- **„გაგზავნა — დან / მდე“** (`field/list.html`) — ნაწილი ა-ში უცვლელი (სერვერი ჯერ გაგზავნის თარიღით ფილტრავს); ნაწილი ბ-ში → „თარიღი — დან / მდე“, ნახაზის თარიღით (T-011).
- **Hallmark** — ბლოკერი არ არის; ჩაბარებისას lead უშვებს.
- `tests/test_ui.py`-ის სამი ტესტი — qa ასწორებს, commit `ui/T-012-lists`-ზე, merge-მდე.

## 2. პრომპტი შემსრულებლისთვის — qa (Codex)

> ბრიფს არ ცვლის — მხოლოდ „როგორ“-ს ამატებს. დასრულების პირობა ნაწილი 1-იდან სიტყვასიტყვით.

### ნაწილი ა — პრომპტი UI შემსრულებლისთვის

**სამუშაო ვერსია, დასადასტურებელი (2026-10-27).** ეს პრომპტი ეხება მხოლოდ ნაწილი ა-ს; ნაწილი ბ-ს დაწყებას და მთელი T-012-ის ჩაბარებას არ ნიშნავს. UI Claude-ს წინასწარი ანალიზი უკვე მზად აქვს — გამოიყენე თავისი არსებული ანალიზი და შეადარე ქვემოთ მოცემულ ფაილებსა და საზღვრებს; თავიდან იმავე ანალიზის მომზადება საჭირო არ არის. ანალიზის ტექსტი ამ დოკუმენტს არ ახლავს, ამიტომ მის დაუდასტურებელ დასკვნებს შეთანხმებულ მოთხოვნად ნუ ჩათვლი.

შენ ხარ ui. მიზანია არსებული სიებიდან ჯგუფური მონიშვნის, დაფის და header-ის გლობალური ძებნის ამოღება და წარწერებისა და QC „გასავლელის“ სვეტების გამარტივება. ნაწილი ა მუშაობს ახლანდელი backend-ის ცვლადებით; `flt` კონტრაქტი და ახალი ფილტრები T-011-ის ჩაბარების შემდეგ, ნაწილი ბ-ში გამოიყენება.

### საზღვრები და უსაფრთხო გარემო

- წაიკითხე `AGENTS.md`, `docs/team/roles/ui.md`, `docs/team/SALOME.md`, `DESIGN.md` და ამოცანის ნაწილი 1. სამუშაო ბრენჩია `ui/T-012-lists`; თუ ის უკვე არსებობს და ანალიზი/სამუშაო აქვს, შეინარჩუნე. main-ში არ იმუშაო და არ ატვირთო. ამ პრომპტის მომზადების ეტაპზე commit/push არ კეთდება; შემსრულებლის შემდგომი ჩაბარება ცალკე ავტორიზებულ სამუშაოს ეკუთვნის.
- ნაწილი ა-ს **დადასტურებული მოცულობაა ბრიფის 4–7**: checkbox/bulk/board-ის ამოღება, წარწერები, QC „გასავლელის“ სტატუსისა და კოდების სვეტების დამალვა, header-ის `cmdk`-ის წაშლა. როლის გადამრთველი რჩება.
- **ნაწილი ბ-ში რჩება 1–3:** ერთიანი ფილტრის მაკრო და ორი ხაზის განლაგება, ზონა/სექტორის ახალი ქცევა, თარიღების ახალი კონტრაქტი, `per` 10–30, ჩაწერადი მენეჯერი/ამზომველი და მათი API, `flt.show_operator` / `flt.show_status` / `flt.limited` / `flt.empty_range`, ველის სიის ანონიმურობის სრული პუნქტი 3. ნაწილი ა-ში ესენი არ მოიგონო და `flt` არ მოითხოვო. არსებული ველის სიის კონფიდენციალურობა არ გააუარესო; აღმოჩენილი გაჟონვა ცალკე აღწერე T-015/ნაწილი ბ-ს დამოკიდებულებით.
- ბრიფის **პუნქტი 8** და „გასავლელის“ **სტატუსის ფილტრი** ქვემოთ გამოყოფილია ლუკასთან დასაზუსტებლად; დაუდასტურებლად ნაწილი ა-ს მოცულობას ნუ დაამატებ. უკვე ნებადართული 4–7-ის შესრულება ამ პასუხების მოლოდინში შეიძლება გაგრძელდეს.
- ნაწილი ა-ს კოდი: `app/templates/base.html`, `app/templates/qc/list.html`, `qc/_table.html`, `qc/disputes.html`, `qc/checked.html`, `app/templates/field/list.html`, `field/_table.html`, `app/static/js/app.js`, საჭიროებისამებრ `app/static/css/app.css`. სხვა შაბლონები შეეხე მხოლოდ მაშინ, თუ იმავე მოსაშლელი მექანიზმის ფაქტობრივი გამოყენება იპოვე და ეს ბრიფის 4–7-ში ჯდება.
