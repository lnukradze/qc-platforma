## 1. ბრიფი — lead

**მიზანი:** ლუკას გადაწყვეტილება (`docs/OPEN_QUESTIONS.md`, „კომენტარის რედაქტირება“): კომენტარი იცვლება მხოლოდ „რედაქტირებით“ (ინტერფეისი — T-016);
ყოველ შენახვას ლოგი აქვს; ჩანს „ბოლო ცვლილება — ვინ · დრო“. QC მენეჯერს გადაწყვეტილების შემდეგ ახსნის რედაქტირება შეუძლია.
კონტროლის ცვლილებების ლოგს ველი ვერ ხედავს; კონტროლი ველის ლოგს ხედავს.

**წინაპირობა:** T-015 (`actor_name`) ჩაბარებულია.

**შედის:**
1. `edited`-ის `data`-ს ემატება `{"field": "qc_comment", "before": …, "after": …}`.
2. ახალი ქმედება **`qcm_comment_edit`** (QC მენეჯერი, ადმინი; როცა `item.qcm_decision` არის): ცვლის `item.qcm_explanation`-ს; მოვლენა `qcm_comment_edited` `before/after`-ით;
   ცარიელი ახსნა `qcm_stand`-ზე — უარი (როგორც ახლა). `available_actions`-ში — სწორ როლსა და მდგომარეობაზე. `version` — T-019-ის წესით.
3. ველის კომენტარის რედაქტირება (ამზომველი / მენეჯერი, სანამ ოქმი ისევ ველზეა): ქმედება **`field_comment_edit`**, მოვლენა `field_comment_edited` `before/after`-ით (კონტროლს უჩანს).
4. QC-ის რედაქტირების მოვლენები (`edited`, `qcm_comment_edited`) — `scope.QC_INTERNAL_EVENTS`-ში (ველს არ უჩანს).
5. ბარათს `last_change`: `{"qc_comment" | "field_comment" | "qcm_explanation": {"at", "who"} | None}` — `who` უკვე `actor_name`-ით (ველისთვის „ხარისხის კონტროლი“).

**არ შედის:** შაბლონები (T-016); ანონიმურობის სხვა ზედაპირები (T-015).

**ფაილები (ზონა):** `app/workflow.py`, `app/scope.py`, `app/routes/items.py`, `tests/test_comment_log.py` (ახალი — ნებადართული გამონაკლისი).

**კონტრაქტი (backend ↔ ui):** `last_change` (ზემოთ); ქმედებები `qcm_comment_edit`, `field_comment_edit` — POST `/items/{id}/action`, ველები `comment`, `version`;
მოვლენის `data.before` / `data.after` — ისტორიაში QC-სთვის.

**დასრულების პირობა** (ტესტირებადი):
1. `edited` / `qcm_comment_edited` ველის ისტორიაში არ ჩანს; QC-ის ისტორიაში ჩანს `before/after`-ით; `field_comment_edited` კონტროლს ჩანს.
2. `qcm_comment_edit`: QC მენეჯერი — მუშაობს; ოპერატორი / საველე — უარი; გადაწყვეტილების გარეშე — უარი.
3. `last_change` სწორია სამივე კომენტარზე; ველისთვის `who` = „ხარისხის კონტროლი“.
4. `pytest -q` გადის; `smoke_pages.py` დემო ბაზაზე — 0 შეცდომა.

**ჩაბარებისას შევამოწმებ:** უსაფრთხოება — ქმედების უფლება სერვერზე; ველს QC ლოგი არ უჩანს.
