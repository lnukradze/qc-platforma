## 1. ბრიფი — lead

**მიზანი:** ლუკამ რეალურ ბაზაზე საველე მენეჯრით ნახა (2026-10-28): ძველი ცხრილიდან გადმოტანილი ოქმის **ისტორიაში** ჩანს QC ოპერატორის
სახელი და გვარი. მიზეზი: ძველ Google ცხრილში ჩანართს ოპერატორის სახელი ერქვა, იმპორტი კი ამ სახელს ინახავს
(`services/legacy_import.py`: `legacy_source = r["_tab"]`, `op_name = … or r["_tab"]`) და ბეჭდავს:
- `items/detail.html:16` — ბარათის თავის ნიშანი „ძველი ცხრილიდან · `legacy_source`, მწკრ. N“ — **ყველა როლს**;
- `items/detail.html` ისტორია — `legacy_import` მოვლენის კომენტარი „ძველი ცხრილი — <ჩანართი>, მწკრივი N“ (`legacy_import.py:342`) — **ყველა როლს**;
- `routes/api.py` → `_event_json` — იგივე `comment` ველის როლსაც.

რეალურ ბაზაში ასეთი ~44 ათასი ოქმია. **დემოში არცერთი** (`build_demo_db.py` ძველ ოქმებს არ ქმნის), ამიტომ T-015, T-029, T-031-ის
შემოწმებებმა ეს ვერ დაიჭირა. ⚠️ ლუკას სკრინშოტზე ნამდვილი სახელია — **არსად** გადაიტანოთ (კოდი, ტესტი, commit, ოქმი).

**წესი** — უცვლელი (ლუკა, 2026-10-27, T-031): ველის როლს QC-ის სახელი და როლი **არსად** უჩანს. ძველი ცხრილის ოქმზე ველს:
ნიშანი — მხოლოდ „ძველი ცხრილიდან“ (წყაროს და მწკრივის გარეშე); `legacy_import` მოვლენის კომენტარი — **არ ჩანს** (HTML, API).
QC როლებს, ადმინს და კოორდინატორს ყველაფერი რჩება, როგორც ახლაა. არსებული მონაცემი ბაზაში **არ იცვლება** — წესი ჩვენებისას მოქმედებს.

**კონტრაქტი (backend ↔ ui):** ნაწილი ბ ამატებს `services/anon.py`-ში და `render()`-ის კონტექსტში (მნახველის როლით მიბმულს, როგორც `actor_name`):
- `legacy_tag(item)` → `str`: ველს — „ძველი ცხრილიდან“; სხვას — „ძველი ცხრილიდან · {legacy_source}, მწკრ. {legacy_row}“ (როგორც ახლა);
- `event_comment(e)` → `str | None`: ველს `legacy_import`-ზე — `None`; სხვა შემთხვევაში — `e.comment`.

### ნაწილი ბ — backend

**შედის:**
1. `services/anon.py`: `legacy_tag(viewer_role, item)`, `event_comment(viewer_role, event)` — ერთი წესი HTML-ისთვის და API-სთვის.
2. `routes/common.py` → `render()`: ორივე, მნახველის როლით მიბმული, კონტექსტში.
3. `routes/api.py` → `_event_json`: `"comment": anon.event_comment(viewer_role, e)`. გადაამოწმე, API-ს სხვა ველში ძველი ცხრილის ჩანართი ხომ არ ბრუნდება.
4. `services/legacy_import.py` — **მომავლისთვის**: კომენტარი ჩანართის გარეშე („ძველი ცხრილი, მწკრივი N“), ჩანართი — `data["tab"]`-ში.
   არსებულ ჩანაწერებს არ ეხები (რეალურ ბაზას აგენტი არ ხსნის; ჩვენების წესი მათაც ფარავს).
5. `scripts/build_demo_db.py` — 3–5 ძველი ცხრილის ოქმი, რეალურის მსგავსად: `is_legacy=True`, `legacy_source` = დემო QC ოპერატორის სრული სახელი,
   `legacy_row`, `legacy_import` მოვლენა **ძველი ფორმატის** კომენტარით (სახელით) და `data.snapshot`-ით; ერთი მაინც — დემო საველე მენეჯერსა
   და ამზომველს ხილული (`scope.field_visible`). ასე smoke, QA და lead ამ გზას დემოზეც ხედავენ.

**ფაილები (ზონა):** `app/services/anon.py`, `app/routes/common.py`, `app/routes/api.py`, `app/services/legacy_import.py`, `scripts/build_demo_db.py`.

### ნაწილი ა — ui

**შედის:**
1. `items/detail.html:16` — ნიშანი: `{{ legacy_tag(item) }}`.
2. `items/detail.html` ისტორია — კომენტარი `event_comment(e)`-დან (`None` → ბლოკი არ იხატება).
3. გადაამოწმე **ყველა** გვერდი, რომელიც ველს უჩანს: `legacy_source`, მოვლენის კომენტარი ან ძველი ცხრილის ჩანართი სხვაგან ხომ არ იბეჭდება.
   T-016 (ბარათის ახალი ვერსია) ამ ორ ფუნქციას იყენებს — პირდაპირ `item.legacy_source` / `e.comment` ველისთვის აღარ.

**ფაილები (ზონა):** `app/templates/`. ნაწილი ა ნაწილ ბ-ს ელოდება (ფუნქციები კონტექსტში) — ან ერთ ბრენჩზე, ან ბ-ს შემდეგ.

### ნაწილი გ — qa

**შედის:** რეგრესიის ტესტი (`tests/`), რომელიც ამ გზას მომავალშიც იცავს:
- ძველი ცხრილის ოქმი, `legacy_source` და `legacy_import` კომენტარი = QC ოპერატორის სრული სახელი (გამოგონილი);
- **ორივე ველის როლით:** `/items/{id}` HTML და `/api/items/{id}` JSON — **არცერთი** QC როლის (`qc_operator`, `qc_manager`, `admin`)
  მომხმარებლის სრული სახელი (ზოგადი შემოწმება ყველა QC მომხმარებელზე, არა ერთ სახელზე); ნიშანი „ძველი ცხრილიდან“ — ჩანს;
- QC ოპერატორით, QC მენეჯრით და ადმინით — წყარო ჩანს (როგორც ახლა).
T-028-ის კონფიდენციალურობის ნაწილი ძველი ცხრილის ოქმებსაც უნდა ფარავდეს.
