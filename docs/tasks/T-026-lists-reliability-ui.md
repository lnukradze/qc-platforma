## 1. ბრიფი — lead

**მიზანი:** HTMX სიები ორ შემთხვევაში იშლება და შეცდომას არ აჩვენებს (DESIGN.md წესი 5 — ცარიელი / იტვირთება / შეცდომა).
წყარო — `docs/reports/T-008-ui-audit.md` (U-09 – U-12, U-23, U-29), `docs/tasks/T-004-design-audit.md` (A04).

**წინაპირობა:** T-012 (იგივე ფაილები) და T-022 (`HX-Redirect`, `HX-History-Restore-Request`) ჩაბარებულია.

**შედის:**
1. U-09: ბრაუზერის „უკან“ HTMX-ის ქეშის გარეშე — სრული გვერდი (მენიუ და ფილტრები რჩება).
2. U-10: ვადაგასული სესია — `HX-Redirect`-ით შესვლის გვერდზე გადასვლა (არა ცხრილში ჩასმა).
3. U-11: `htmx:responseError` / `htmx:sendError` → შეტყობინება სიის ადგილას + „ხელახლა ცდა“.
4. U-12, A04: „იტვირთება“ — სწორ ელემენტზე (`hx-indicator`), `aria-busy`.
5. U-23: presence — ფონურ ჩანართში (`document.hidden`) სიგნალი ჩერდება.
6. U-29: განაწილების `<style>.htmx-indicator…</style>` — `app.css`-ში ერთხელ.

**არ შედის:** Python (T-022); სიების განლაგება (T-012).

**ფაილები (ზონა):** `app/static/js/app.js`, `app/static/js/presence.js`, `app/static/css/app.css`, `app/templates/` (სიები, განაწილება).

**კონტრაქტი (backend ↔ ui):** `HX-Redirect` (T-022).

**დასრულების პირობა** (ტესტირებადი):
1. ფილტრი → სხვა გვერდი → „უკან“ (localStorage გასუფთავებული) → სრული გვერდი.
2. სესიის cookie წაშლა → ფილტრი → შესვლის გვერდი მთელ ფანჯარაში.
3. სერვერის გაჩერება → ფილტრი → შეცდომის შეტყობინება და „ხელახლა ცდა“; სერვერის ჩართვა → მუშაობს.
4. ნელი ქსელი (DevTools) → „იტვირთება“ ჩანს.
5. ფონურ ჩანართში 2 წთ → presence-ის მოთხოვნები არ იგზავნება.
6. კონსოლი სუფთა; `pytest -q` გადის; Hallmark — ახალი FAIL არ გაჩნდა.

**ჩაბარებისას შევამოწმებ:** ბრაუზერში 1–5 თავად.
