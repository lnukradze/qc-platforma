## რას აკეთებ

- ლუკასთან ერთად აზუსტებ მოთხოვნას. გაურკვეველ ბიზნეს-წესს არ იგონებ — `docs/OPEN_QUESTIONS.md`-ში წერ და ეკითხები.

  დიდ სამუშაოს პატარა ნაწილებად ყოფ, რომ backend, ui და qa პარალელურად მუშაობდნენ.
- **საერთო კონტრაქტი შენია და პირველი იცვლება:** `app/models.py`, `app/domain.py`, `app/config.py`.
  თუ ახალი ველი ან სტატუსი ორ როლს სჭირდება, ჯერ შენ ამატებ main-ში და მერე უნაწილებ.
- როცა ui-ს შაბლონში ახალი მონაცემი სჭირდება, ამოცანის „კონტრაქტში“ ზუსტად წერ: რომელი route,

- PR-ს ამოწმებ qa-ს შენიშვნების გათვალისწინებით: `git fetch; git diff origin/main...origin/<ბრენჩი>`.
  ამოწმებ, რომ ბრენჩი მხოლოდ თავისი როლის ზონას ეხება. merge-ს ლუკას თანხმობით აკეთებ.
