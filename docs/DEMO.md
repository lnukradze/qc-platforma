# წარდგენის სცენარი — ხელმძღვანელობა და IT (≈ 25 წუთი)

> მიზანი: ერთ ცოცხალ ოქმზე სრული ციკლის ჩვენება:
> **განაწილება → შემოწმება → ველის „არ ვეთანხმები“ → მენეჯერის დადასტურება → QC მენეჯერის გადაწყვეტილება → გასწორება → სტატისტიკა**.
> ამის შემდეგ — სტატუსის შეცვლის მოთხოვნა, დაუჯგუფებელი, სპორადული, Pre-QC, ტელეფონი და IT.

## მომზადება (10 წუთით ადრე)

1. **სუფთა ბაზა:** სერვერი გააჩერეთ და გაუშვით `.venv\Scripts\python.exe scripts\build_db.py` (≈ 2 წთ). ასე წინა ჩვენების ცვლილებები წაიშლება.
2. `run.bat` → <http://127.0.0.1:8200>.
3. **მეორე ფანჯარა** (Incognito / InPrivate) — ორი ადამიანის ერთდროული მუშაობის საჩვენებლად (ყვითელი ნიშანი).
4. ტელეფონისთვის: `run_lan.bat`. ფანჯარაში ჩანს მისამართი და **PIN**; ტელეფონი იმავე Wi-Fi-ში უნდა იყოს.
5. გასვლა ზედა მარჯვენა კუთხეშია. ვისაც რამდენიმე როლი აქვს, როლს ზედა ზოლში ცვლის. ადამიანს შესვლის გვერდზე ძებნით პოულობთ.

## მთავარი სათქმელი (30 წამი)

- **ერთი სისტემა** ხუთი ინსტრუმენტის ნაცვლად: ცხრილი, Apps Script, განაწილების პროგრამა, სტატისტიკის პანელი, Pre-QC.
- **წესებს სისტემა იცავს:** ვინ რას ხედავს, ვინ რას პასუხობს, რა არის სავალდებულო. მაგალითად, „ველი მართალია“ „დადებითის“ მონიშვნის გარეშე არ შეინახება.
- **ციფრები ყველასთვის ერთნაირად ითვლება.** ოპერატორის დღე = პირველი გაგზავნის დღე. მერე აღარ იცვლება.
- **ყველაფერი ისტორიაში რჩება** — ვინ, რა როლით, როდის.
- მონაცემი **რეალურია**: ძველი ცხრილის 44 538 მწკრივი → 44 159 შემთხვევა (379 დუბლიკატი მოცილდა). სადემონსტრაციოა Pre-QC და ორი ანგარიში — კოორდინატორი და სამსახურის უფროსი.
