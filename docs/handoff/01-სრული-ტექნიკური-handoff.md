## 1. მოკლე შეჯამება

**ტექნიკურად:** ვაშენებთ როლებზე დაფუძნებულ (RBAC) ვებ-აპლიკაციას — FastAPI (Python), სერვერზე აწყობილი HTML გვერდები (Jinja2 + HTMX) და რელაციური ბაზა (SQLAlchemy 2; პროტოტიპში SQLite, საწარმოოში PostgreSQL). აპლიკაცია ერთ სისტემაში აერთიანებს ოქმების განაწილებას, QC შემოწმებას, ველის პასუხების სამუშაო პროცესს (state machine სრული ისტორიით), სტატისტიკას და Pre-QC-ის შედეგებს. სააგენტოს წყარო სისტემებს მხოლოდ კითხულობს.

**მარტივად რომ ავხსნათ:** დღეს ხარისხის კონტროლი ხუთ სხვადასხვა ხელსაწყოზეა გაბნეული: Google ცხრილი, მისი სკრიპტები, განაწილების პროგრამა ერთ კომპიუტერზე, სტატისტიკის საიტი და Pre-QC პროგრამა. ვაკეთებთ ერთ საიტს, სადაც ყველა თანამშრომელი შედის საკუთარი ანგარიშით და ხედავს მხოლოდ იმას, რაც მის საქმეს ეხება. ოქმი იქვე ნაწილდება, მოწმდება, ველზე მიდის, ბრუნდება და იხურება, სტატისტიკა კი თავისით ითვლება.

### 8.2 შემოთავაზებული (საწარმოო) 💡 ❓

```
მომხმარებელი (ოფისი / ველი, ტელეფონი)
      │ HTTPS 443 (qc.<სააგენტოს დომენი>)

      │ HTTP, localhost ან შიდა ქსელი
      ▼
აპლიკაციის სერვერი (VM, Linux ან Windows Server; სასურველია Docker)
  ├─ ვებ-პროცესი: uvicorn / gunicorn, N worker (სერვისად, ავტომატური რესტარტით)
  ├─ ფონური worker + განრიგი: ღამის იმპორტი, მეილის რიგი, presence-ის გასუფთავება
  └─ ფაილების საცავი (ფოტო/PDF) — ლოკალური დისკი ან ქსელური საცავი, ბექაპით

      ▼

  ├─ აპლიკაციის მომხმარებელი (მხოლოდ ჩვენი სქემა)
  ├─ ღამის ბექაპი + WAL არქივი (PITR)
  └─ მიგრაციის მომხმარებელი (სქემის ცვლილებისთვის)

გამავალი კავშირები: Google OAuth (accounts.google.com, oauth2.googleapis.com), SMTP relay
შიდა წყაროები (მხოლოდ კითხვა): REGFIELDALL view/ექსპორტი, სპორადულის view, 🗓 ოქმის API, WFS
```

**მარტივად რომ ავხსნათ:**
- **Reverse proxy** სახლის კარია: დაცული შესასვლელი (HTTPS), რომელიც სტუმარს სწორ ოთახში ატარებს.
- **აპლიკაციის სერვერი** სამზარეულოა, სადაც საქმე კეთდება.
- **ფონური worker** ღამის მორიგეა: ახალ მონაცემს იღებს და მეილებს აგზავნის, ისე რომ მომხმარებელს არ ალოდინებს.
- **PostgreSQL** სეიფია, სადაც ყველა ჩანაწერი ინახება და ყოველ ღამე ასლი კეთდება.

ყველა ეს ნაწილი შეიძლება **ერთ ვირტუალურ სერვერზე** იყოს; გაყოფა სავალდებულო არ არის (იხ. [სახელმძღვანელო §A.10](02-პირადი-ტექნიკური-სახელმძღვანელო.md)).
