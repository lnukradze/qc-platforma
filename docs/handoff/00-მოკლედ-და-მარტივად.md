# QC პლატფორმა — მოკლედ და მარტივად

> ვისთვის: ლუკასა და სალომესთვის, IT შეხვედრისთვის. წასაკითხია 10 წუთში.
> დეტალები საჭიროების შემთხვევაში დანარჩენ ექვს დოკუმენტშია (README.md).

---

## 1. რა არის ეს

**ერთი საიტი, რომელიც ხუთ ცალკე ხელსაწყოს ცვლის:** Google ცხრილს, მის სკრიპტებს, განაწილების პროგრამას, სტატისტიკის საიტს და Pre-QC-ს.

ოქმი ერთ ადგილას ნაწილდება, მოწმდება, ველზე მიდის, ბრუნდება და იხურება. ყოველი ნაბიჯი ინახება: ვინ, რა და როდის გააკეთა. სტატისტიკა თავისით ითვლება.

**დღეს:** ჩემს კომპიუტერზე მუშაობს, რეალურ მონაცემზე (44 159 შემთხვევა). სააგენტოს სისტემებს მხოლოდ კითხულობს და არაფერს წერს.

## 2. რატომ არ გვყოფნის ცხრილი

- 30 000-ზე მეტი მწკრივია და ნელია;
- სტატუსი ზედ იწერება, ამიტომ ისტორია იკარგება;
- წესებს ადამიანები იცავენ და არა სისტემა;
- ძველი ცხრილიდან გადმოტანისას 379 დუბლიკატი აღმოჩნდა;
- განაწილების პროგრამა ერთ კომპიუტერზეა მიბმული.

## 3. როგორ არის აწყობილი (ძალიან მარტივად)

| ნაწილი | რა არის | მარტივად |
|---|---|---|
| **Python** (FastAPI) | პროგრამის „ტვინი“ | წყვეტს, ვინ რას ხედავს და რა შეუძლია |
| **ბაზა** | მონაცემების შესანახი ადგილი | ახლა SQLite (ერთი ფაილი), საწარმოოში PostgreSQL |
| **HTML + პატარა JavaScript** | გვერდები | სერვერი მზა გვერდს აგზავნის, ბრაუზერი აჩვენებს |
| **Google შესვლა** | ვინ არის თანამშრომელი | პაროლს ჩვენ არ ვინახავთ |

**ორი მთავარი წესი:**
1. სერვერი ყოველ ჯერზე თვითონ ამოწმებს, ვის რა შეუძლია. სხვისი ოქმი არ ჩანს.
2. ყოველი ცვლილება ისტორიაში იწერება და არასოდეს იშლება.

## 4. რა გვჭირდება IT-სგან

**პილოტისთვის (ჯერ მცირე ჯგუფი):**

1. **ერთი ვირტუალური სერვერი** (ჩვენი შეფასებით 4 პროცესორი, 8 GB, 100 GB. ეს შეფასებაა, პილოტზე გავზომავთ);
2. **PostgreSQL ბაზა** (თქვენს არსებულ სერვერზეც შეიძლება);
3. **ბაზის ბექაპი** (ყოველ ღამე, სხვა ადგილას);
4. **დომენი და HTTPS** (Google შესვლას სჭირდება);
5. **Google-ის OAuth client** სააგენტოს სახელზე (მხოლოდ სახელი და ელფოსტა);
6. **გამავალი კავშირი** სერვერიდან Google-თან.

**მერე:**
- ველიდან ტელეფონით შესვლა (საჯარო HTTPS ან VPN);
- მეილი (SMTP);
- REGFIELDALL-ის და სპორადულის სიის წაკითხვა (read-only);
- Pre-QC-ისთვის ოქმის მონაცემზე წვდომა.

## 5. გულწრფელად: რა არ არის მზად

**ჩვენი მხრიდან:**
- PostgreSQL-ზე ჯერ არ გაგვიშვია (გადასვლა და ტესტირება ჩვენი სამუშაოა);
- დატვირთვის ტესტი არ ჩატარებულა;
- დემო შესვლა საწარმოოში უნდა გაითიშოს;
- ბაზაში ელფოსტა არავის აქვს (მენეჯერები უნდა შეგროვდეს);
- პროექტი ჯერ git-ში არ არის.

**გადასაწყვეტი:**
- სპორადულის ფილტრები;
- კოორდინატორისა და სამსახურის უფროსის როლები;
- Pre-QC დღეს დემოა და სერვერზე მუშაობას ოფიციალური გზა უნდა.

## 7. ხშირი კითხვები — მოკლე პასუხებით

| კითხვა | პასუხი |
|---|---|
| **რატომ არა ჩვენი ბაზა?** | თქვენსას მხოლოდ ვკითხულობთ. ჩვენს სამუშაოს ცალკე ადგილი სჭირდება (თქვენს სერვერზეც შეიძლება). |
| **რატომ PostgreSQL და არა SQL Server?** | უფასოა და ჩვენი სხვა პროექტი მასზეა. SQL Server-ზეც გადავიტანთ, ტესტირებით. |
| **ცალკე სერვერი რატომ?** | ჩემს კომპიუტერზე ვერ დარჩება: ითიშება, ბექაპი არ აქვს. ერთი ვირტუალური სერვერი საკმარისია. |
| **100 ადამიანი ერთდროულად?** | ჩვეულებრივი დატვირთვაა, მაგრამ ტესტამდე ციფრს ვერ დაგპირდებით. |
| **დისკი?** | ბაზა დღეს 94 MB-ია. ზრდა რამდენიმე GB წელიწადში (შეფასება). |
| **ინტერნეტის გარეშე?** | შიგნით მუშაობს. გარეთ მხოლოდ Google-ის შესვლა გადის. |
| **მონაცემი როგორ მოდის?** | ღამით, საჭირო ველების ასლი. თქვენს სისტემებში არაფერს ვწერთ. |
| **ციფრები ზუსტია?** | ერთი ფორმულა ყველასთვის. ძველ შემაჯამებელს ყოველ ოპერატორზე დაემთხვა. |
| **ბექაპი?** | ყოველ ღამე; სრული გაშვებისთვის წუთობრივი აღდგენა. სასურველია თქვენი სისტემით. |
| **ვინ ადმინისტრირებს?** | აპლიკაციას ჩვენ ორნი. სერვერს და ბაზას — თქვენთან ვთავაზობთ. |
| **თანამშრომელი წავიდა?** | ერთი ღილაკით ვთიშავთ, მყისიერად მოქმედებს. HR-ისგან შეტყობინება გვჭირდება. |
| **განახლება როგორ?** | ჯერ სატესტოზე, მერე საწარმოოში. შეფერხება წამებია. |
| **უსაფრთხოება?** | Google შესვლა, უფლებები სერვერზე, სხვისი ოქმი „ვერ მოიძებნა“, ისტორია არ იშლება. ცნობილ ხარვეზებს თვითონ ჩამოგითვლით. |
| **Pre-QC სერვერზე?** | დღეს თანამშრომლის ბრაუზერის სესიით მუშაობს. სერვერისთვის ოფიციალური გზა (API) გვჭირდება. მოგვიანებით ეტაპია. |

## 8. შეხვედრის მიზანი

დღეს უნდა შევთანხმდეთ ერთზე: **ვინ გამოყოფს სერვერს და ბაზას, და დაახლოებით როდის.** დანარჩენს ჩვენ პარალელურად ვაკეთებთ.

**თუ რამე არ ვიცით:** „ზუსტად არ ვიცი, ჩავიწერ და მოგწერ.“
